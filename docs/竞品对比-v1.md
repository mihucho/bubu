## 三、三个关键发现

### 发现 1：几乎所有同类产品都有「家长确认」这一层

OurHome、S'moresUp、iRewardChart、Joon、作业小达人 —— 全部是 **孩子提交 → 家长确认 → 发奖**。

我们故意没有（1-tap 完成），理由是"不打断节奏"。但对比后发现：**这一层不只是防作弊，它有情感价值**——"我做的事被爸爸看到了"。

> **修正 M1**：任务级可选 `need_confirm`（默认关）。与已有拍照形成两级：
> **拍照 = 证据**，**确认 = 认可**。作业类可开，阅读类不必开。

### 发现 2：没有一个中文产品在做「AI 陪伴复盘」

Joon 是游戏化，作业小达人是打卡 + 排行，宝宝巴士是内容。**"基于真实数据、记得住孩子说过的话、会复盘"的位置是空的。**

这既是最大差异点，也是最大风险（家长会问"AI 会不会乱说"）——我们做的工具化 + 数字白名单 + 危机信令，恰好是护城河。

### 发现 3：竞品几乎都做「比较」

作业小达人有排行榜、Duolingo 有联赛、ClassDojo 有班级名次。
二孩场景下这条路必须继续不走，并把「零比较」变成**可以对外讲的卖点**。

## 四、7 个值得借鉴的机制

| # | 机制 | 来源 | 我们的用法 |
| --- | --- | --- | --- |
| 1 | 提交 → 确认 | OurHome / 作业小达人 | 任务级 `need_confirm`，默认关（**M1**） |
| 2 | 拍照/录音/附件多形态提交 | 作业小达人 | 已有拍照；**录音**作为朗读类证据（M4，P1） |
| 3 | 奖励商店由家长定价 | OurHome / iRewardChart | 已有（商店 + 心愿） |
| 4 | 家长"点评"而非只打分 | 作业小达人 | 家长端加**一句鼓励**（M2） |
| 5 | 提醒驱动 | S'moresUp | 家长端提醒（M3，**优先级最高**） |
| 6 | 行为曲线而非单一分数 | iRewardChart | 周期报告已有分组 + 柱状 |
| 7 | 游戏内成长（不兑现真钱） | Joon | 宠物 / 布布成长（P1） |

## 五、5 个明确不学

| 不学 | 来源 | 原因 |
| --- | --- | --- |
| 公开排行榜 / 联赛 | Duolingo · 作业小达人 · ClassDojo | 6–10 岁 + 二孩 = 压力源 |
| 真钱奖励（零花钱卡/投资） | BusyKid | 把学习变成打工；且涉及支付合规 |
| 纯时长控制当核心卖点 | 宝宝巴士 | 我们做使用管理，但不拿它当卖点 |
| 无目标纯玩 | Toca Boca | 与"激励闭环"定位冲突 |
| 全程盯梢式家长监控 | 各类家长控制 App | 立场是"看见变化"，不是"看着孩子" |

## 六、对我们方案的 5 条修正

| # | 修正 | 落点 |
| --- | --- | --- |
| **M1** | 任务新增 `need_confirm`（要家长确认），默认关；提交后进「待确认」，确认才发星 | 数据模型 / 孩子端打卡流 / 家长端待处理 |
| **M2** | 家长端「给孩子一句鼓励」；孩子端首页显示 24 小时 | 家长概览 / 孩子端首页 |
| **M3** | 提醒机制（任务未完成 / 心愿待定价 / 报告生成） | 家长端设置 + 应用内通知中心 |
| **M4** | 提交形态扩展：录音（朗读、背诵） | P1 |
| **M5** | 把「零比较 · 不兑现真钱 · 有 AI 复盘」写成对外三条卖点 | 定位 |

---

## 七、结论

> 机制上，我们与 OurHome / Joon 同族（任务 → 积分 → 兑换 → 报告），但**少了一层"家长确认"**，这是最值得补的一层。
> 位置上，我们是唯一把 **AI 陪伴 + 零比较 + 周期报告** 三件事合在一起的产品，这是最值得守的部分。
