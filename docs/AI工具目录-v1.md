# AI 工具目录 v1（34 个）

> 配套 `AI对话-工具化改造-v4.md`（架构）与 `最终方案-v2.0.md §8.2`（决策）。
> 本文只回答一件事：**布布能查什么、不能查什么、查了之后能不能动手。**

---

## 一、四类工具，一条铁律

| 类 | 权限 | 数量 | 说明 |
| --- | --- | --- | --- |
| **K · 孩子端只读** | `ctx.childId` 强制注入 | 18 | 只能查自己，物理上查不到别人 |
| **P · 家长端只读** | `ctx.familyId` + 显式 `child_id` | 11 | 可跨孩子，但只做并列 |
| **S · 系统** | 无业务数据 | 3 | 时间、帮助、政策片段 |
| **D · 提议（propose）** | 不写库，只产草稿 | 4 | 返回一张"确认卡"，由人点确认才落库 |

> **铁律：模型永远不能写库。** 所有"动手"都走「提议 → 人确认 → 正常 REST 接口写」，这样写操作的鉴权、校验、审计一条都不绕过。

**三条通用约束（继承 v4）**
1. 参数里**永不出现 `childId`**（除 P 类家长工具，且必须校验属于本家庭）。
2. 统一外壳 `{ ok, as_of, data, empty, truncated? }`。
3. 单轮 ≤3 次调用；单工具 <150ms；结果 >2KB 截断。

1. `child_id` 必须属于 `ctx.familyId`，否则 `forbidden`。

## 五、D · 提议类（4）— 会"动手"，但只出草稿

**工作方式**

```
家长说「给老大建个每天跳绳 100 个的任务」
  → 模型调 propose_task_draft
  → 工具返回 draft（不写库）
  → 前端渲染「确认卡」：任务名 / 周期 / 目标 / 奖励 / 拍照
  → 家长点「就这么建」→ 走正常 POST /parent/tasks → 落库 + 审计
  → 家长点「改一下」→ 回到对话继续
```

| # | 工具 | 触发场景 | 返回草稿字段 | 落库接口 |
| --- | --- | --- | --- | --- |
| D1 | `propose_task_draft` | "帮我建个任务" | name, cycle, target, stars, photo_mode, need_confirm | `POST /parent/tasks` |
| D2 | `propose_wish_price` | "这个心愿该定多少星" | title, suggested_cost, basis（参考同类心愿） | `PATCH /parent/wishes/:id` |
| D3 | `propose_badge_draft` | "给她建个系鞋带的徽章" | name, icon_key, rule_type, star_reward, praise_text | `POST /parent/badges` |
| D4 | `propose_encouragement` | "帮我想句鼓励的话" | text（≤40 字）, target_child_id | `POST /parent/messages` |

**为什么这样设计**

| 风险 | 用 propose 规避 |
| --- | --- |
| 模型误建任务/误发消息 | 必须人点确认，模型永远无法独立落库 |
| 奖励数值被 AI 改大 | 草稿里的 `stars` 有上限（≤3），且确认卡上高亮 |
| 审计缺失 | 落库走正常接口，`audit_logs` 记 `actor=parent, source=ai_draft` |
| 孩子端被 AI 代操作 | 孩子端**没有**任何 propose 工具，只有只读 |

**提议类不做的事**：不批量（一次一张卡）、不自动执行、不在孩子端出现。

### 5.1 确认卡交互规格（原型已画：`/parent/chat/proposal`）

| 规则 | 说明 |
| --- | --- |
| **一张卡一次** | 不做批量，避免"AI 一口气改了 8 个任务" |
| **卡上必须写四件事** | 改什么 · 改成什么 · 代价（几颗星）· 两个按钮（改一下 / 就这么建） |
| **不能跳过** | 模型永不落库；点确认走正常业务接口，审计记 `actor=parent, source=ai_draft` |
| **改一下不删卡** | 卡留在原位变成「已废弃」，家长能回看 AI 原本想干什么 |
| **星数硬顶** | 草稿奖励 ≤3 颗，卡上高亮，防 AI 把奖励调大 |
| **孩子端没有这张卡** | 孩子端零 propose 工具，"让布布帮我打卡"物理上做不到 |

草稿卡的字段与落库接口：

```
任务草稿        任务名 / 周期 / 目标 / 达标奖励 / 拍照 / 需要我确认
                → POST /parent/tasks
鼓励草稿        「一句话」/ 发给谁 / 字数 x/40
                → POST /parent/messages
心愿定价草稿    标题 / 建议星数 / 依据
                → PATCH /parent/wishes/:id
徽章草稿        名字 / 图标 / 条件 / 奖励 / 颁奖语
                → POST /parent/badges
```

## 六、预算与降级

| 项 | 值 | 超了怎么办 |
| --- | --- | --- |
| 单轮工具调用 | ≤3 | 强制收尾，用已有数据作答 |
| 单工具耗时 | <150ms | 超时返回 `tool_error`，模型话术"这个我暂时看不到" |
| 结果大小 | ≤2KB | 截断 + `truncated: true` |
| 一轮总耗时 | ≤9s | 直接返回已生成部分 |
| 工具失败重试 | 不重试 | 同一工具一轮最多 1 次，避免死循环 |

**失败话术白名单**（不许自由发挥）：

```
这个我暂时看不到   /   还没有记录
要问爸爸妈妈才知道 /   我记不清了，你再说一次
```

### 6.1 降级界面规格（原型：`/parent/chat/degraded` · `/chat/degraded`）

| 规则 | 家长端 | 孩子端 |
| --- | --- | --- |
| **必须给出路** | 每句道歉后跟三个按钮：再问一次 / 看周期报告 / 看记录 | 一句话 + 一个按钮：再问一次 / 去看我的阅读 |
| **不甩技术词** | 只说"数据服务忙""今天问满了" | 只说"这个我暂时看不到" |
| **不中断当前轮** | 次数用完在**下一轮**生效，当前这轮答完再提示 | 同 |
| **不装懂** | 不猜数字、不拿上次数字当这次 | 孩子说"你猜猜嘛" → "我猜不准，怕说错了骗到你" |
| **不连累别处** | 报告 / 记录 / 任务全部照常 | 任务 / 阅读 / 运动 / 商店全部照常 |

> 孩子端那句"我猜不准，怕说错了骗到你"是刻意的：6–8 岁对数字的信任一旦破了，就再也找不回来。

## 七、工具清单的可见性（产品要求）

家长端「我的 → 布布能做什么」列出**全部 34 个工具**，分四组展示，并明确标注：

- 孩子端 18 个：**只读**，只能看自己
- 家长端 11 个：可跨孩子，**并列不排名**
- 系统 3 个：时间 / 帮助 / 政策
- 提议 4 个：**必须你确认才会生效**

为什么给家长看这个清单：AI 的能力边界是家长最焦虑的部分，写清楚比解释一百句"我们很安全"有用。
