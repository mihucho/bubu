# 数据模型设计 v1

> 前置：`docs/整体设计优化-v1.md`（派生优先、事件优先、幂等、时间单点）
> 说明：本项目 `server/database/schema.ts` 由平台生成（`npm run gen:db-schema`），**不要手改**。本文是建表依据，按此在平台建表后重新生成。

---

## 一、七条设计原则

1. **孩子是数据域**：所有业务数据挂 `child_id`；`family_account_id` 冗余保存，仅用于家庭级校验与统计。
2. **事件优先**：动作先落事件表（打卡/彩蛋/使用），计数器只作读缓存，可随时重建。
3. **派生优先**：本周星星、本周达标、进度、趋势一律从事件与流水算，不做定时重置。
4. **单一真相**：星星只有 `star_ledger` 一个来源；`available_stars` / `total_stars` 是它的事务内缓存。
5. **幂等**：所有写操作带 `idempotency_key` 唯一约束，重试与连点天然安全。
6. **快照**：兑换记录、周报、日报保存当时快照（名称、价格），避免改名改价污染历史。
7. **时间带时区语义**：所有业务"日"用 `local_date`（`Asia/Shanghai`），时间戳用 `timestamptz`。

**类型约定**

| 用途 | 类型 |
| --- | --- |
| 主键 | `uuid default gen_random_uuid()` |
| 短文本 | `varchar(n)`（n 按实际给，不一律 255） |
| 枚举 | `varchar(20)` + 应用层常量；不用 pg enum（改起来麻烦） |
| 日期（业务日） | `date` |
| 时刻 | `timestamptz(3)` |
| 结构化快照 | `jsonb` |
| 计数 | `integer` |
| 排序 | `smallint` |

## 六、关键派生查询

```sql
-- ① 本周星星
SELECT COALESCE(SUM(amount), 0) AS week_stars
FROM star_ledger WHERE child_id = $1 AND local_date >= $weekStart AND amount > 0;

-- ② 本周达标数
SELECT COUNT(*) FROM tasks WHERE child_id = $1 AND week_start = $weekStart AND is_achieved;

-- ③ 今日快照（AI 工具 get_today_snapshot 一次查完）
SELECT
  (SELECT COUNT(*) FROM task_checkins WHERE child_id=$1 AND local_date=$today) AS checkins_today,
  (SELECT COALESCE(SUM(minutes),0) FROM reading_records WHERE child_id=$1 AND local_date=$today) AS reading_minutes,
  (SELECT COALESCE(SUM(amount),0) FROM star_ledger WHERE child_id=$1 AND local_date=$today) AS stars_today,
  (SELECT COUNT(*) FROM egg_opens WHERE child_id=$1 AND local_date=$today) AS eggs_today;

-- ④ 星星余额对账（应恒等于 available_stars）
SELECT COALESCE(SUM(amount),0) FROM star_ledger WHERE child_id=$1;

-- ⑤ 心愿可兑现（余额 ≥ 定价）
SELECT w.* FROM wish_items w
JOIN child_profiles c ON c.id = w.child_id
WHERE w.status='priced' AND c.available_stars >= w.star_cost;

-- ⑥ 本周趋势（7 天阅读）
SELECT local_date, SUM(minutes) FROM reading_records
WHERE child_id=$1 AND local_date >= $weekStart
GROUP BY local_date ORDER BY local_date;
```

## 七、加星三件套（唯一写入路径）

```ts
// server/common/stars.service.ts —— 全站唯一允许改星星的地方
async addStars(tx, { childId, familyId, amount, reason, refTable, refId, title, localDate, idemKey }) {
  // 1) 幂等：重复 key 直接返回已有结果
  const existed = await tx.query.starLedger.findFirst({ where: eq(starLedger.idempotencyKey, idemKey) });
  if (existed) return existed;

  // 2) 锁行取余额（防并发）
  const child = await tx.select().from(childProfiles).where(eq(childProfiles.id, childId)).for('update');
  const nextBalance = child.availableStars + amount;
  if (nextBalance < 0) throw new Conflict('INSUFFICIENT_STARS');

  // 3) 写流水 + 更新缓存（同一事务）
  const [ledger] = await tx.insert(starLedger).values({ ... }).returning();
  await tx.update(childProfiles).set({
    availableStars: nextBalance,
    totalStars: amount > 0 ? child.totalStars + amount : child.totalStars,
  }).where(eq(childProfiles.id, childId));
  return ledger;
}
```

**约束**：任何业务模块**不得**直接 `UPDATE child_profiles SET available_stars`；必须走此服务。

## 八、一致性校验（每日跑一次）

| 检查 | SQL 语义 | 告警阈值 |
| --- | --- | --- |
| 余额漂移 | `available_stars` ≠ `SUM(star_ledger.amount)` | 任意 1 条 |
| 任务计数漂移 | `tasks.current_count` ≠ `COUNT(task_checkins)` | >0 |
| 达标不一致 | `is_achieved=true` 但 `current_count < target_count` | >0 |
| 孤儿数据 | 业务表 `child_id` 不存在于 `child_profiles` | >0 |
| 周报缺失 | 上周有活动的孩子无周报 | >0 |

漂移修复策略：以事件/流水为准回写缓存字段，并记一条 `adjust` 流水（金额 0，仅审计用途）。

## 十、Drizzle 片段（对齐生成器风格）

```ts
export const starLedger = pgTable("star_ledger", {
  id: uuid("id").primaryKey().defaultRandom(),
  childId: uuid("child_id").notNull(),
  familyAccountId: uuid("family_account_id").notNull(),
  amount: integer("amount").notNull(),
  reason: varchar("reason", { length: 20 }).notNull(),
  refTable: varchar("ref_table", { length: 30 }),
  refId: uuid("ref_id"),
  title: varchar("title", { length: 60 }),
  balanceAfter: integer("balance_after").notNull(),
  localDate: date("local_date").notNull(),
  idempotencyKey: varchar("idempotency_key", { length: 64 }),
  createdAt: customTimestamptz("_created_at", { precision: 3 }).notNull().default(sql`CURRENT_TIMESTAMP`),
}, (table) => [
  uniqueIndex("uq_ledger_idem").on(table.idempotencyKey),
  index("idx_ledger_child_date").on(table.childId, table.localDate),
]);
```

## 十一、容量与性能估算

| 场景 | 量 | 结论 |
| --- | --- | --- |
| 单孩子年数据 | 打卡 1.5k · 流水 2k · 消息 5k | 单表百万级也够，无需分区 |
| 热点查询 | 首页（今日快照）、账本最近 20 条 | 均有 `(child_id, local_date)` 索引 |
| 需缓存项 | 今日快照 60s、周报（读快照表） | 不做复杂缓存 |
| jsonb 使用 | 报告 payload、工具审计 | 只读展示，不做 jsonb 查询索引 |

## 十二、三条不可违反的规则

> 1. 业务模块**不得**直接改 `available_stars`，只能调 `StarsService`。
> 2. 计数器（`current_count`/`is_achieved`）**必须**能由事件重建；不能重建的计数不许存在。
> 3. 任何写接口**必须**带 `idempotency_key`；没有幂等的写操作不许上线。
