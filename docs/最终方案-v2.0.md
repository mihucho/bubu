# 第二部分 · 产品定义

## 2.1 定位

面向 6–10 岁儿童的家庭学习激励与成长陪伴应用。用星星把行为变成可见正反馈，用 AI 布布陪孩子复盘，用家长端把"配置 + 看见变化"收在一处。

## 2.2 四个核心判断

1. **孩子端不是 dashboard，是一本会动的童话书**——一屏一个大动作 + 一个会发生的惊喜。
2. **家长端不是孩子端的放大版，是另一个产品**——孩子端「少慢有仪式」，家长端「密快能批量」。
3. **家长定义一切 ≠ 让家长先填表**——出厂模板完整可用；目标"首次 3 分钟、之后每次 30 秒"。
4. **AI 的价值在查得准、记得住、不编造**——模型不喂数据，改为调只读工具；数字永不进记忆。

## 2.3 三条产品底线

- 孩子端**永不出现横向比较**（无榜、无"姐姐比你多"、AI 禁生成比较句式）。
- 孩子端**零外链、零购买、零广告、零删除、零"设置"字样**。
- 任何功能故障**不得阻塞打卡**（图片/网络/AI 都是增强项）。

## 3.5 手势与返回

孩子端只允许 **单击 / 上下滚动 / 左右滑（仅说说话气泡）**。禁止长按、双击、拖拽、下拉刷新、侧滑返回。无返回按钮，页面深度 ≤1，详情用底部弹层。

## 3.5.1 家长登录：豆包为主，手机号为辅

```
只需要判断一件事：在不在豆包内（不做微信/浏览器/其它 WebView 的细分）

在豆包内
  ├ 平台身份已绑家庭 → 直接进（不显示任何登录页）
  └ 平台身份未绑定   → 「进入 / 绑定账号」页
        ├ 「进入」→ 以豆包身份新建家庭 → 引导
        └ 「已有账号？绑定账号」→ 输手机号 + 密码 → 并进原有家庭

不在豆包内（微信扫码 / 浏览器 / 其它）
  → 手机号登录页（没有豆包按钮，也没有绑定入口）
```

> 绑定放在主按钮**下面**、做成**文本按钮**：已有账号的是少数，不能抢「进入」的注意力。

**为什么以豆包为主**：家长大概率在豆包里打开，多一步输入就多一层流失；手机号作为"没有豆包时的兜底"保留。

## 3.5.2 账号绑定与数据合并

### 绑定：只在豆包内出现，手机号 + 密码一步到位

| 项 | 规则 |
| --- | --- |
| 出现条件 | **在豆包内打开** 且 平台身份**未绑任何家庭** → 「我的 → 家庭账号」出现「豆包账号 · 未绑定」 |
| 不在哪里出现 | 登录页（浏览器登录用手机号）；孩子端（孩子没有豆包登录） |
| 怎么绑 | 输入**手机号 + 密码** → 校验通过即写 `doubao_user_id` |
| 不做 | 不做跳转授权页（身份已在平台会话里，再跳一次是多余摩擦） |
| 冲突 | 该豆包已绑别的家庭 → 明确报错，不静默合并 |
| 解绑 | 解绑后只能用手机号登录，**孩子数据不变** |

### 合并：把「豆包新建的空家庭」并进「有数据的手机号家庭」

```
浏览器注册（家庭 A：2 个孩子）→ 后来在豆包打开 → 平台身份是新用户 → 系统建了空家庭 B
                                          → 提示「合并到你的手机号账号」→ 执行合并
```

| 规则 | 说明 |
| --- | --- |
| 方向 | 永远并入**有数据的家庭**；空家庭的 `merged_into_id` 指向目标并归档 |
| 孩子 | 改 `family_account_id` 即可 —— **业务数据全挂 child_id，天然跟随**，不搬表 |
| 重复孩子 | 同名 + 相近年龄 **不自动合并**，只标记「看起来是同一个」，由家长勾选归档哪个 |
| 上限 | 合并后 ≤ 6 个孩子，超出先归档 |
| 星星 | 各孩子余额不变（不做跨孩子转账） |
| 拒绝 | 两个豆包绑同一家庭 · 跨租户 · 目标家庭已归档 |
| 留痕 | `audit_logs.action = 'family.merge'`，30 天内可查 |

**为什么合并是低成本操作**：所有业务数据都是 `child_id` 维度，家庭只是孩子的容器。所以"合并家庭"= 改孩子归属 + 归档源家庭，**不需要迁移任何业务表**。

## 3.6 孩子账号：家长开通，孩子自己用

孩子**不注册**。账号由家长开通时生成，孩子拿到的是「账号 + 初始密码」，首次登录后可改成自己的密码。

### 开通（家长端 /parent/enter）

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 账号 account | `BUBU7K2M9X` | **全局唯一**，无横线无空格（展示时可分成 BUBU 7K2M9X），不区分大小写，可复制 |
| 初始密码 | `482913` | 6 位数字，家长生成；可随时重置 |
| 扫码 | `bubu://kid-join?account=BUBU7K2M9X&code=482913` | 孩子平板扫一下自动带出账号与密码 |
| 有效期 | 15 分钟 | 一次性，用完失效 |

### 登录与改密码

```
孩子打开 App
  → 显示账号 BUBU7K2M9X（只读）+ 4–6 位密码键盘
  → 首次登录：自动提示「改成你自己的密码」，可跳过继续用初始密码
  → 之后：只输密码即可（账号已记住）
  → 换设备：重新扫码，或手输账号 + 密码
```

| 规则 | 说明 |
| --- | --- |
| 改密码 | 孩子自助（`我的 → 我的密码`），4–6 位，两步确认 |
| 家长可见性 | 家长只能看到「已改过」，**看不到新密码** |
| 忘记 | 「帮忙」→ 家长门 → 家长端重置为新的初始密码，所有旧设备失效 |
| 出错 | 3 次错误冷却 3 秒 + 「叫爸爸妈妈帮忙」，**不锁死** |

### 家长切到孩子页面

不是预览——**就是孩子的真实页面**，可打卡、可进商店。

| 项 | 规则 |
| --- | --- |
| 顶部细条 | 36px「家长查看中 · 点此返回」，5 秒后淡出，点顶部唤回 |
| 为什么不做只读 | 家长切过来通常是为了"帮他点一下"或"看装扮效果"，只读会让这条路白走 |
| 审计 | 家长在这台设备上的打卡，流水来源记 `parent`，家长端可查 |
| 孩子看不到 | 孩子自己登录时没有细条，也没有「返回家长端」 |

### 三种进入方式的边界

| 场景 | 用哪个 | 孩子密码 |
| --- | --- | --- |
| 家庭共用一台设备 | 选人页 → 孩子账号 → 密码 | 用（区分兄弟姐妹） |
| 孩子有自己的平板 | 扫码 → 账号自动带出 → 首次改密码 | 用（就是他的密码） |
| 家长想看孩子页 | 家长端 → 进入孩子页面 | 不用（家长门已解锁） |

## 4.1 星星经济学

| 项 | 规则 |
| --- | --- |
| 获得 | 见下方「星星来源表」，每个来源的数值都由家长配置 |
| 消耗 | 商店兑换、心愿兑付、宠物食物（P1） |
| 重置 | 本周星星**派生**（流水求和），取消定时重置 |
| 真相 | `star_ledger` 唯一来源；`available_stars`/`total_stars` 为事务内缓存 |
| 汇率 | 取消"1⭐=1元/1分钟动画" |

### 星星来源表（每个来源都可被家长关掉或调数值）

| 来源 | 触发条件 | 默认 | 家长可调 | 防重复 |
| --- | --- | --- | --- | --- |
| 任务 | 某项次数达标 | 按任务 1–3 颗 | ✔ | 达标只给一次 |
| 彩蛋 | 开一个彩蛋 | 1 颗 | ✔ | 每天每个蛋一次 |
| 心情 | 当天写心情 | 2 颗 | ✔（可设 0） | 每天一次 |
| 阅读 | 今日阅读目标达标 | 2 颗 | ✔（可设 0） | 每天一次 |
| **运动** | **本周运动次数达标** | **2 颗** | ✔（可设 0） | 每周一次 |
| **闯关** | **每次通关** | **1 颗** | ✔（可设 0） | 本周新增上限 10 关，超限不计星；「再闯一次」不给星 |

### 三条给星原则

1. **给星对应"完成"，不对应"记录"**——记录只是进度，达标才给星，否则可以刷。
2. **同一次达标只入账一次**，靠 `star_ledger.ref_id` 唯一性保证。
3. **没达标也要有反馈**：运动给火苗推进、闯关给关卡进度，只是不给星——避免"白干"的感觉。

### 为什么运动不是"每次给星"

每次运动都给星会诱导孩子为了星星虚报次数，且把运动变成交易。改成 **周目标达标给一次 2 颗**，既保持目标感，又不鼓励刷。

### 任务周期（不是所有任务都按"本周"算）

| 周期类型 | 说明 | 例子 | 孩子端分区 |
| --- | --- | --- | --- |
| `daily` 每天 | 每天重置，今天做几次算达标 | 每天阅读 5 次 · 每天口算 3 次 | **今天要做** |
| `weekly` 每周 N 次 | 一周内累计 N 次 | 每周运动 3 次 · 每周作业 7 次 | **本周要做** |
| `weekly_days` 每周固定几天 | 周一/三/五必做 | 周一三五练琴 | 今天要做（只在指定日出现） |
| `monthly` 每月 N 次 | 一个月内累计 N 次 | 每月读一本整书 | 本月要做 |
| `once` 一次性 | 有截止日期，做完就消失 | 春游前准备清单 | 待完成（带截止日） |
| `custom` 自定义区间 | 起止日期内累计 N 次 | 寒假 20 次跳绳 | 自定义区间 |

**达标口径统一为「一个周期内完成 N 次」**，统计与页面呈现都按任务自己的周期走，不再假设"一周"。

### 首页宝箱改成「今日宝箱」

| 项 | 规则 |
| --- | --- |
| 分母 | **今天要做的任务数**（`daily` + 今天应有的 `weekly_days`） |
| 分子 | 今天已达标的任务数 |
| 为什么 | 每天都有即时反馈；周/月目标放在各自分区的标题里（"本周要做 2/3 已达标"） |
| 兜底 | 今天没有每日任务时，宝箱显示"今天没有安排"而不是 0/0 |

### 分区的固定顺序

```
今天要做  →  本周要做  →  本月要做  →  一次性（带截止日）
```

每个分区标题右侧显示该分区的达标进度；任务行显示自己的周期徽标（每天 / 每周 3 次 / 每月 2 次），避免"为什么这个任务一直不消失"的困惑。

### 周期报告（替代周报）

任务周期可以是每天 / 每周 / 每月 / 一次性，所以报告**不再绑定"周"**，而是两层时间概念：

| 概念 | 作用 | 选项 |
| --- | --- | --- |
| **报告区间** | 区间统计（阅读 · 运动 · 星星 · 心情） | 最近 7 天 / 最近 30 天 / 自定义 |
| **任务周期** | 每个任务按自己的周期各自计数 | 每天 / 每周 / 每月 / 一次性 |

**报告结构**

```
每天的任务     7 天完成率 + 每日柱状 + 每个任务 x/7 天
每周的任务     本周 x/y 达标 + 每个任务 x/y 次
每月 / 一次性   本月 x/y + 待完成（带截止日）
区间统计       阅读 / 运动 / 心情 / 星星收支
布布看到       2 条观察
接下来可以这样  1 条建议
[保存图片]
```

**为什么不用"本周达标 3/6"这个口径**：任务有 4 种周期，分母不可加；按周期分组才能让家长看懂"哪些事稳定、哪些事在掉"。

### 为什么闯关可以"每次给星"

做题是有真实成本的（比"记录一次运动"重），所以按次给更公平；靠**周新增上限 10 关**和「再闯一次不给星」防刷。

| 层级 | 触发 | 反馈 |
| --- | --- | --- |
| 单次 | 点 +1 未达标 | 盖章 + 星星飞入 + 轻音效（≤1.1s） |
| 达标 | 次数满 | 翻绿 + 「+N⭐」气泡 + 语音（≤5 次/天） |
| 周达标 | 宝箱满 | 全屏撒星 3s 可跳过 + 宝箱开启 |

## 4.4 徽章：系统 8 个 + 家长自定义

| 类型 | 数量 | 谁定义 | 能否改 | 奖励 |
| --- | --- | --- | --- | --- |
| 系统徽章 | 8 个 | 产品 | ❌ 不可改 | 随成就给星（走 `star_ledger`） |
| 家长自定义 | 每孩子 ≤6 个 | 家长 | ✔ 可改可删（**已颁发不能删**） | **默认 0 颗**，可上调至 3 颗 |

**系统徽章（固定 8 个）**：第一次开宝箱 · 连续阅读 3 天 · 运动周达标 · 写完 10 篇心情 · 通关 10 关 · 攒到 100 颗星 · 连续 7 天都来了 · 试试 3 种运动。

**家长自定义的四步**：起名字（≤8 字）→ 选图标 → 定条件 → 写一句颁奖话。条件四选一：

```
星星数    累计得到 N 颗星
连续天    连续 N 天有记录
做几次    某个任务累计做满 N 次
手工发    由家长点「颁发」才发出（不自动补发）
```

**四条约束**

1. **默认不给星**：徽章是纪念，不是货币。给星上限 3 颗，避免"建徽章 = 刷星通道"。
2. **只和自己比**：徽章页没有任何榜单，未获得只显示灰色 + 进度，不显示"失败"。
3. **已颁发的不能删**：删除只对未颁发的生效；已颁发可"隐藏"，但保留孩子端历史。
4. **孩子看到的样子要预览**：编辑页底部实时预览（图标 + 名字 + 「妈妈给你的」+ 那句话）。

**孩子端位置**：我的 → 徽章，排系统徽章之后，标注「妈妈给你的」。

# 第五部分 · 完成方式与媒体（本轮新增重点）

## 5.1 拍照的两个独立属性：**是否显示 / 是否必填**

不把打卡做成「两种模式」，而是给任务两个**正交开关**：

| 字段 | 含义 | 默认 |
| --- | --- | --- |
| `photo_visible` | 这个任务**显示不显示拍照入口**（卡片上的 📷 徽标、打卡时的拍照按钮） | **true** |
| `photo_required` | 拍照**是不是必填**（不拍就不算完成）。为 true 时必然 `photo_visible = true` | false |

**四种组合，三种合法**

| 显示 | 必填 | 孩子看到什么 | 适用 |
| --- | --- | --- | --- |
| ✗ | ✗ | 只有 `+1`，全程无拍照（家长主动关掉显示时才有） | 不想看到任何拍照入口的极简任务 |
| **✓** | **✗** | **默认**：卡片有 📷 徽标，`+1` 即可完成，**也能顺手拍一张** | 全部任务默认都在这一格 |
| ✓ | ✓ | 必须拍照才算完成；取消 = 不计次数 | 学校作业、写字练习、画画 |
| ✗ | ✓ | **非法**（必填却不显示，孩子无法完成）→ 数据层约束：`photo_required ⇒ photo_visible` | — |

> 用两个布尔而不是一个枚举，好处是「可选拍照」这种中间态天然存在，不用额外造字段；坏处只有一条——必须加约束防止非法组合。

**核心规则**

- 「必填」模式下**取消即不完成**（不计次数、不给星）。不能先完成后补图，否则证据不成立。
- 「显示但不填」模式下，孩子可以拍照，也可以不拍；照片事后仍可补（最多 3 张）。
- **不设「允许跳过」配置**；家长临时想放行，用一次性动作（见 §5.1.2），避免开关越加越多。

### 5.1.1 设置时机：**创建任务时确定**


拍照是任务的**两个字段**（`photo_visible` / `photo_required`），在**创建/编辑任务的表单里**设置，不做全局开关。

**创建任务表单（5 步，一屏）**

```
① 任务名称       [ 写数学作业        ]
② 图标           [系统图标] [上传/拍照] [豆包画]   ← 三个并列入口
③ 一周要做几次    [－]  5  [＋]
④ 完成得几颗星    [－]  3  [＋]
⑤ 拍照片         [ 不需要 ][ 可选 ][ 必填 ]   ← 三选一，**默认「可选」**
                              [ 保存 ]
```

「三选一」与两个字段的映射：
| 三选一 | `photo_visible` | `photo_required` |
| --- | --- | --- |
| 可选（**默认**） | true | false |
| 必填 | true | true |
| 不需要（家长主动关） | false | false |

**默认值**：新任务一律**显示**（=「可选」）——拍照入口默认就有，但不强制；家长想收掉再选「不需要」，想强制再选「必填」。

**编辑与继承**

| 场景 | 行为 |
| --- | --- |
| 创建后改「必填」 | 已完成的次数保留，**只影响之后的打卡** |
| 改回「不需要」 | 已拍的图保留可查看，不再要求 |
| 复制上周 / 复制到另一个孩子 | 沿带 `photo_visible` + `photo_required`（只复制定义，不复制进度与图片） |
| 模板预置的任务 | 按模板映射给默认值（见下） |

**模板的默认值**

| 任务 | 默认 |
| --- | --- |
| 全部模板任务（作业/阅读/口算/家务/运动） | **可选**（显示入口，不强制） |
| 家长想强制留证的（如学校作业） | 自行改成「必填」 |

> 判据：**能留下一张纸或一个作品、且家长想验证的，才设为必填**；过程型任务一拍就变成负担。

**微文案（家长端帮助）**

> 选「可选」时：「孩子可以拍一张留个纪念，不拍也能完成。」
> 选「必填」时：「孩子要先拍一张照片，这次打卡才算数。」

### 5.1.2 家长临时放行（一次性动作，不是配置）

「必填」模式下偶尔会遇到作业本不在手上。**不做常驻开关**（开关一多家长就不看了），改用一次性动作：

```
家长端 · 概览 · 孩子卡片 [待处理]
  └── 小月亮有 1 个任务要拍照才能完成
        [ 这次先放行 ]   ← 仅本次有效，次日失效
```

- 放行后孩子端该任务变回 `+1` 一次即可完成，卡片上标注「这次不用拍照」。
- 放行记录写审计（谁放的、什么时候、哪个任务），家长端可见。
- 放行不写进任务配置，**只作用于当天那一次**。
## 5.2 拍照流程

```
拍照模式：点任务行 → 相机（系统 capture）→ 本地压缩（≤1MB, 长边1600）
        → 预览 + [拍一张][相册][重拍] → [✓ 完成]
        → 立即入账（不等上传）→ 后台传 → 失败标 media_pending 重试
```

三条硬规则：**不弹系统选图框**（直接用 capture）· **先压缩再上传** · **完成判定不等上传**。

## 5.3 任务图标（三来源）

```
icon_file（上传/AI） > icon_key（系统 12 个 SVG） > 关键词兜底
```
- 家长端：`[系统图标] [上传/拍照] [豆包画]`；
- 上传后裁 1:1、长边 512、JPEG 0.82、≤200KB；
- AI 生成 → `uploadFromUrl` → 落自己的桶（防第三方 URL 过期）；
- 失败回退 `icon_key` 且**保存不阻塞**。

## 5.4 头像

- 孩子端：仅 6 个预设（立即生效，无上传）；
- 家长端：预设 / 相册 / 拍照；
- 双字段：`avatar_key`（永远有）+ `avatar_file`（可空）。

## 5.9.3 站内消息的双通道

| 收件人 | 入口 | 内容 | 已读 |
| --- | --- | --- | --- |
| 孩子 | 首页右上信封 + 我的 | 家长鼓励 · 心愿定价/可兑现 · 新关卡 · 布布的发现 | 红点 |
| 家长 | 概览铃铛 + 我的 | 要你处理 · 孩子动态 · 系统 | 红点 + 未读计数 |

家长端「我发出的」可查看自己发过的每一句鼓励与**孩子是否已读**——发出去的话不可撤回（"被夸过"要留痕）。

发送时**可选收件人**：单发一个孩子，或「两个都发」；落库按孩子各一条，已读状态独立。

## 5.9.4 安全信令（需要关注）

孩子对话命中安全词（害怕 / 被打 / 没人喜欢我 / 不想活）时：

1. 该条消息 `safety_flag = true`，**永久保留**，不参与记忆压缩
2. 家长端「需要关注」置顶：原话 + 布布当时的回复 + **怎么开口的建议**
3. 孩子端不出现任何"你被标记了"的痕迹
4. 家长标记「已关注」后仍保留记录

## 5.10 家长确认与鼓励（竞品对比后的修正）

### 为什么补「家长确认」

OurHome / S'moresUp / iRewardChart / Joon / 作业小达人 **全部**是「孩子提交 → 家长确认 → 发奖」。
我们原本 1-tap 完成，缺了这层。但对比后确认：**这不只是防作弊，是"我做的事被看到了"**。

### 两个开关，语义不同

| 开关 | 默认 | 语义 | 谁用 |
| --- | --- | --- | --- |
| `photo_required` | false | **证据**：不拍不算完成 | 作业、写字、画画 |
| `need_confirm` | false | **认可**：家长确认后才发星 | 需要家长点头的任务 |

两者可叠加：`拍照 + 确认` = 先交证据再被认可。

### 打卡流变化

```
need_confirm = false    点 +1 → 立即完成 → 星星入账
need_confirm = true     点 +1 → 提交 → 「等爸爸妈妈确认」→ 家长确认 → 星星入账
                                   └ 家长点"让他再做一次" → 回到未完成，不发星
```

| 项 | 规则 |
| --- | --- |
| 孩子端 | 待确认的任务显示「等爸爸妈妈确认」，**不可再点**，但不算完成、不给星 |
| 家长端 | 概览出现「待确认 N」，可「确认」或「让他再做一次」 |
| 超时 | 超过 24 小时未确认，自动视为通过（避免孩子白等） |
| 审计 | 确认人、确认时间写入 `task_checkins.confirmed_by/confirmed_at` |

### 家长鼓励（M2）

家长端可写**一句话**（≤40 字），孩子端首页在布布气泡下方显示 24 小时，带一个心形图标。
不是打分、不是评价，只是"我看到了"。默认不写。

**收件人可选**：一句话可以选一个孩子，也可以选「两个都发」。

**孩子端头像**：孩子只能从 **8 个预设**里挑；上传照片只能由家长在家长端做（避免孩子拍到家人或不当内容）。

| 项 | 规则 |
| --- | --- |
| 选择 | 多选 chips（小月亮 / 小米粒 / 两个都发） |
| 落库 | **每个孩子一条消息**（`messages` 一行一孩），互不共享已读状态 |
| 已读 | 家长端「我发出的」显示每个孩子各自的已读/未读 |
| 撤回 | **不可撤回**——"被夸过"要留痕 |
| 内容 | 40 字以内，不做模板群发（避免变成通知广播） |

### 提醒（M3）

**决策：只做站内消息。**
不做飞书 / 微信 / 短信推送——不引入外部账号授权、模板审批与额外成本；提醒统一收在应用内通知中心。

```
孩子端：不推送、不弹窗；站内消息只在小信箱里，带一个小红点
家长端：站内通知中心（铃铛红点）· 打开应用才看到
```

**方案（不依赖平台）**：自建应用内通知中心

```
notifications(id, family_account_id, child_id, kind, title, payload, read_at, created_at)
```

| 场景 | 触发 | 孩子端 | 家长端 |
| --- | --- | --- | --- |
| 任务待确认 | 孩子提交 | — | 概览红点 + 「待确认 N」 |
| 心愿待定价 | 孩子提愿 | 心愿卡「等定价」 | 概览「待处理」 |
| 可兑现 | 攒满 | 心愿卡「可以找妈妈兑现」 | 概览「待兑现」 |
| 报告生成 | 每 7 天 | — | 一次应用内提示 |
| 今天还没做 | 20:00 检查 | 布布气泡提醒 | 家长端不推送（不制造焦虑） |

**不属于本期范围**：外部推送（飞书消息插件 / 微信服务号 / 短信）。若后续要做，只需在 `NotificationChannel` 上加一个实现，不改业务逻辑。

## 5.9.2 事后补救（缺了这些，用户会觉得"这 App 无法挽回"）

| --- | --- | --- |

## 5.9 心愿（家长端 /parent/wishes）

心愿是唯一「孩子提、家长定价」的双向机制，独立成页，不塞进商店页——否则家长会漏掉待定价。

### 四段队列

```
待定价 → 攒星中 → 可兑现 → 已兑现
```

| 段 | 家长能做什么 |
| --- | --- |
| 待定价 | 定价（给建议区间）、改图标、延后、删除 |
| 攒星中 | 调价（只影响未来）、转惊喜、取消 |
| 可兑现 | 标记已兑现（写 star_ledger 的 wish 流水） |
| 已兑现 | 归档，可在孩子端账本看到「我为它攒过星」 |

### 五条设置项

| 设置 | 默认 | 作用 |
| --- | --- | --- |
| 允许孩子自己提心愿 | 开 | 关掉后孩子端「+ 我有一个新愿望」隐藏 |
| 同时攒星中上限 | 3 个 | 目标太多孩子会失去焦点；达上限时孩子端新愿望按钮置灰并提示"先把现在的心愿完成吧" |
| 心愿默认有效期 | 90 天 | 到期自动归档为 expired，避免陈年心愿堆积 |
| 新心愿默认惊喜 | 关 | 开启后新心愿默认不给孩子看 |
| 定价建议 | 开 | 显示建议区间 + 按最近 4 周攒星速度估算需要几周 |

### 三个关键规则

1. **定价辅助而非定价强制**：给区间（基于家庭历史已兑现心愿的中位价 × 0.6–1.5）与预估周数；**预估 > 8 周时提示"这个有点远，要不要拆成小目标"**，避免孩子长期攒不到而挫败。
2. **惊喜模式**：家长可把心愿设为孩子端不可见（生日礼物、年底大件）。孩子端完全不出现，但家长端仍可查看进度。
3. **不做"驳回"，做"温和延后"**：孩子端显示「这个以后再说」+ 家长写的替代建议（如"换成这周末去看天文馆？"），不出现"被拒绝"。

### 心愿字段（wish_items 扩展）

```
status        pending | priced | claimable | claimed | rejected_to_claim | expired
is_surprise   boolean  default false      -- 孩子端不可见
fulfill_type  gift | experience | screen_time | cash | other
expires_at    date     null               -- 空=长期
note          text     null               -- 家长备注（孩子端可见）
defer_reason  text     null               -- 延后原因（温和文案）
created_by    kid | parent                -- 家长可代提
```

### 家庭级心愿设置（放 family_accounts）

```
wish_allow_kid_create   boolean default true
wish_max_active         smallint default 3
wish_default_expire_days smallint default 90
wish_new_as_surprise    boolean default false
```

# 第八部分 · AI 布布

## 8.1 架构

```
ChatSessionService（L0 12 条 + L1 摘要 + L2 画像 + 静态 system）
  → AgentLoop（≤3 步：选工具 → 执行 → 出答案）
  → ToolRegistry（只读 · 强制 childId · 裁剪 · as_of）
```

插件若不支持原生 tools，走**路径 B**（规划轮输出 JSON），接口层抽象，切换只改一处。

## 8.2 工具（11 个，P0 做 8）

`get_today_snapshot`（复合，覆盖 80% 场景）· `get_child_profile` · `get_week_tasks` · `get_star_ledger` · `get_reading` · `get_exercise` · `get_mood_notes` · `get_wrong_questions` · `get_shop_items` · `get_wish_progress` · `get_reward_rules`

统一返回 `{ ok, as_of, data, empty }`；**参数永不含 childId**（服务端注入）。

## 8.3 记忆分层

| 层 | 内容 | 预算 |
| --- | --- | --- |
| L0 | 最近 12 条原文 | 1200 token |
| L1 | 滚动摘要（体量恒定 ≤200 字） | 300 |
| L2 | 稳定事实/禁忌 ≤10 条 | 300 |
| system | 人设 + 铁律 | 800 |

**四条压缩原则**：只压提示词视图（原文只增不删）· **数字不进记忆**（会过期并诱发编造）· 情绪与承诺永不压缩掉 · 异步可回退可重建。
**危机例外**：命中危机词 → `safety_flag` 永久保留 + 当轮安抚 + 家长端「需要关注」，优先级高于所有 token 预算。

## 8.3.1 长期记忆（L2 的产品化）

L2 不是"向量库"，是**一张能看、能改、能删的事实表**（`chat_memory_facts`）。

**记什么 / 不记什么**

| 记 | 不记 |
| --- | --- |
| 偏好（喜欢恐龙、喜欢草莓味） | 聊天原文 |
| 禁忌（不喜欢大声的地方） | 成绩、分数、排名 |
| 在学什么（在学钢琴） | 家长说过的话 |
| 情绪线索（考试前会紧张、怕黑） | 健康/身体数据 |

**三条产品规则**

1. **数字不进记忆**（与 §8.3 同一条铁律）：会过期并诱发编造。轮数、星星数、分钟数一律走工具查询。
2. **说出来比默默存好**：命中抽取时，孩子端出现一张「布布记住了：你喜欢恐龙」小卡 + 「说点别的 / 不对哦」。点「不对哦」→ 布布重问一次，旧事实 `deleted_at`。
3. **双向可见**：孩子端「我的 → 布布记得我」、家长端「我的 → 内容与隐私 → 布布记得什么」。两边都能删，删除后布布不再引用。

**边界**

| 项 | 规则 |
| --- | --- |
| 上限 | 每孩子 ≤10 条（超了按 `last_seen` 淘汰） |
| 家长端定位 | **被动可查，不推送**：不进每日汇总、不生成提醒、不进周期报告 |
| 危机例外 | 命中危机词 → 走 `safety_flag` 通道（永久保留 + 家长端「需要关注」），不属于记忆 |
| 删除 | 软删（`deleted_at`），保留审计；孩子看到的是"布布不提了" |

## 8.4 防编造三道闸

事实源唯一（工具）→ 数字白名单校验（不匹配则自检重写一次）→ 空态强制话术（`empty:true` 必须出现"还没有记录"）。

## 8.5 预算

工具 ≤3 次/轮 · 总 ≤9s · 单工具 ≤800ms · 孩子端回复 ≤120 token（≤40 字/条）。

# 第九部分 · 引导与合规

## 8.6 平台官方插件（已确认存在的三项能力）

平台（妙搭/aPaaS）官方插件市场提供以下能力，均可像 AI 对话那样通过 `CapabilityService.load('<id>').call(...)` 调用：

| 插件 | 用途 | 用在哪 | 状态 |
| --- | --- | --- | --- |
| ~~发送飞书消息~~ | 会话卡片 / 飞书消息 | —（**暂不做**：提醒只做站内） | 不做 |
| **文生图** | 文本生成图片 | 家长添加任务时的「豆包画」图标 | P1；**替代自接豆包 API** |
| **文件解析** | 解析图片/文档 | 错题拍照后自动提取题目文字 | P2；错题自动命名与归类 |

**依赖**：这三项都需要在平台「能力/插件」里添加一次，生成 `server/capabilities/<id>.json`，把 pluginKey 填进来即可。

**P0 不受阻塞**：
- 提醒 → **只做站内**（应用内通知中心 + 红点），不做外部推送
- 图标 → 系统 12 个 SVG + 家长上传图片
- 错题 → 先存照片，不做 OCR

## 8.6.1 AI 额度归属与可用范围

**结论：AI 额度属于「应用」，不属于用户的豆包账号。**

依据：能力调用打到 `POST /app/{appId}/__runtime__/api/v1/plugin_server/capability/{id}/execute`，
鉴权用**应用凭证**（服务端）或**平台会话 cookie**（客户端），计费挂在应用/租户上。

| 调用方式 | 鉴权 | 额度归属 | 是否要求用户在豆包 |
| --- | --- | --- | --- |
| 服务端 `CapabilityService`（当前 `/chat/stream` 走这条） | 应用凭证 | **应用（我们）** | 不要求 |
| 客户端 `CapabilityClient` | 平台 SSO cookie | 应用（同一个 app） | 要求且必须同源 |

→ 所以**微信 / 浏览器用户也会消耗我们的额度**，必须显式设计边界。

### 决策：AI 只在豆包内可用

| 环境 | 说说话 | 理由 |
| --- | --- | --- |
| 在豆包内 | 正常对话 + 快捷气泡 | 平台会话在，能力调用最稳 |
| 不在豆包内（微信 / 浏览器） | **只读**：显示历史消息 + 一句「布布只在豆包里陪你聊天」+「让爸爸妈妈用豆包打开」 | ① 不消耗应用额度 ② 儿童 AI 入口收敛更合规 ③ 避免微信流量白嫖成本 |

### 配套的三道闸（服务端）

1. **入口闸**：`POST /chat/stream` 校验 `inDoubao` 标记（由前端上报 + 服务端校验 UA/会话来源），不在豆包内直接返回 `403 AI_UNAVAILABLE`，前端渲染只读态。
2. **限频闸**：每家庭 **60 轮/天**、每孩子 **20 轮/天**、单轮最多 3 次工具调用（防脚本刷）。
3. **日报缓存闸**：AI 成长日报**每天只生成一次**并落 `ai_daily_reports`，之后所有人读缓存，不重复计费。

### 成本量级（用于定价与上限设定）

| 项 | 估算 |
| --- | --- |
| 单轮对话 token | 输入 2–4k（system + 历史 + 工具结果）/ 输出 ≤120 |
| 单孩子日均对话 | 5–15 轮（限频 20 封顶） |
| 单家庭日成本 | 主要由对话轮数决定，日报为固定 1 次 |
| 结论 | 限频 + 日报缓存后，成本可预测；**不做"全端开放 + 无限频"** |

## 8.6.2 两端 AI 的边界

| | 孩子端「说说话」 | 家长端「问布布」 |
| --- | --- | --- |
| 数据范围 | **只看自己**（永不跨孩子） | **可以看全部孩子**（默认全部，可切单孩） |
| 在豆包内 | 正常对话 | 正常对话 |
| 不在豆包内（微信/浏览器） | **只读**（不消耗应用额度） | **可用**（限 30 轮/天/家庭） |
| 限频 | 20 轮/天/孩子 | 30 轮/天/家庭 |
| 工具集 | child scope 11 个只读工具 | parent scope：`list_children` / `get_child_snapshot` / `get_family_range` / `get_pending_confirm` / `get_task_templates` |
| 语气 | 陪伴、短句、≤40 字 | 陈述 + 并列 + 「可以先试试」 |

**为什么家长端放开到微信、孩子端不放开**：家长是决策者，AI 问答是其核心价值（"这周到底怎么样"），低频且目的明确；孩子端是高频陪聊，最易被刷，且儿童 AI 入口应收敛。

**家长端 AI 的零比较铁律**（写进 system prompt + 输出后置校验）

```
允许：并列数字（"小月亮 3 本、小星星 1 本"）
允许：各自趋势（"小月亮稳定，小星星周末更活跃"）
禁止：排名（谁第一）、定性比较（谁更好/更差/落后）、归因比较（谁更努力）
被追问"谁更好" → 只给并列 + 一句「两个孩子的节奏不一样」
建议句一律以「可以先试试…」开头，不写「你应该…」
```

**入口**：家长端 5 个 tab 不变；`/parent/chat` 从**概览右上角**与**报告页底部「就这份报告问布布」**进入。

## 9.1 引导 8 屏

```
登录/注册 → 隐私与监护人同意（唯一不可跳过）
 → 欢迎（可跳）→ 添加孩子（预设头像/昵称/几岁/称谓）
 → 选模板（按年龄预选）→ 预览将启用的任务与商店
```

首次体验 5 步（同时只出现一个气泡）：点击提示 → 盖章 → 宝箱说明 → 商店许愿 → 布布先开口。

| 14 岁以下监护人同意 | PIPL | 引导首屏 + `consent_at/version` |

**家长密码**：家长自设 **6 位数字密码**（引导第 6 步设置）；通过后 20 分钟内免重复输入；连续 5 次错误静默退回孩子端；忘记密码走手机号验证码重置。

### 9.2.1 语音：平台没有接口，国内也没有"免费好用"的浏览器方案

**一、平台侧（已逐个 SDK 核对）**

| 包 | 语音相关 |
| --- | --- |
| `client-toolkit`（含 `aily-chat`）、`auth-sdk`、`client-capability`、`fullstack-nestjs-core`、`dataloom`、`aily-web-sdk` | **全部为 0**（搜 `speech/asr/tts/voice/audio/transcribe`） |

已知官方插件：智能写作、文生图、文件解析、发送飞书消息、创建群组。**语音插件是否存在需在插件市场确认。**

**二、Web Speech API 的真实可用性（关键修正）**

| 事实 | 来源 |
| --- | --- |
| Safari 14.1+ 才有 `webkitSpeechRecognition`（需前缀，且**要求开启 Siri**） | caniuse / Apple 社区 |
| Chrome 的识别**依赖服务端引擎**（Google 服务） | MDN：`using Speech Recognition ... involves a server-based recognition engine` |
| **国内网络下 Chrome 的识别基本不可用**（引擎不可达），国内安卓浏览器普遍阉割 | 推断 + 社区反馈 |
| **小程序 / 应用内 WebView 里 `getUserMedia` 常直接失败**：微信小程序 webview 内不弹授权，报 `NotAllowedError: Failed due to shutdown` | 微信开放社区实测贴 |
| 离线方案 whisper.cpp 可 WASM 运行（MIT） | whisper.cpp 官方 |

**结论：Web Speech 不能作为国内 P0 主路径。** 豆包 webview 内更可能完全拿不到麦克风。

**三、候选方案对比**

| 方案 | 免费额度 | 成本 | 儿童语音出境 | 工程 | 判定 |
| --- | --- | --- | --- | --- | --- |
| **不接语音识别**（只留气泡 + 文字） | — | 0 | 无 | 零 | **P0 采用** |
| 平台语音插件 | 待确认 | 待确认 | 平台内 | 最低（同 AI 对话） | P1 首选（若有） |
| 腾讯云「一句话识别」 | **5000 次/月**（录音文件 10 小时/月、实时 5 小时/月） | 后付费按次 | 境内云，需告知同意 | 后端代理 + 密钥 | P1 备选 |
| 讯飞语音听写 | 有免费档 | **¥5.9–9.9/小时** | 同上 | 同上 | P1 备选 |
| 百度短语音 | 有免费额度 | 阶梯按次 | 同上 | 同上 | P1 备选 |
| whisper.cpp WASM（离线） | 全免费 | 0 | **不出设备** | 模型 39–75MB、移动端首载慢、中文一般 | P2 探索 |
| Web Speech API | 浏览器自带 | 0 | 取决于浏览器厂商 | 最简单 | **不作为主路径** |

**四、产品决策**

```
P0：语音按钮不做 —— 说说话只有「快捷气泡 + 文字输入」
    （国内 Chrome 不可用、豆包 webview 大概率拿不到麦克风，做了也用不了）
P1：优先接平台语音插件；没有则接腾讯云一句话识别（5000 次/月对单家庭绰绰有余）
P2：离线 whisper.cpp，仅当"绝不把儿童语音传出去"成为硬要求时
```

**五、如果要做语音（P1），三条约束**

1. **永远是增强**：麦克风旁必留 4 个快捷气泡，识别失败不报错。
2. **必须有一次显式同意**：首次使用弹「把你说的话变成文字需要上传一小段录音」+ 家长确认（儿童个人信息）。
3. **不存原始音频**：转写完成即丢弃，只留文字；`star_ledger`/`messages` 里不出现音频。

**六、在原型里的处理**

`说说话` 页的麦克风按钮标注为 **"P1 · 待平台插件确认"**，主输入是气泡与文字。语音录制页保留为设计稿（说明实现路径），但**不进 P0 范围**。

## 9.3 孩子密码（孩子自己的锁）

| 项 | 规则 |
| --- | --- |
| 定位 | 保护「进入我的小天地」这一个动作；挡的是兄弟姐妹，不是大人 |
| 形态 | 4 位数字（大键盘 62px），选人页点卡片后输入 |
| 默认 | 孩子可主动设（入口在孩子端「我的」）；家长端「孩子管理」也可为该孩子开启/关闭。单孩子且未设置时不出现 |
| 设置入口 | **孩子端「我的 → 我的密码」，由孩子自己设**（两步确认）；已设过的先输旧密码。**家长端不设密码，只做重置** |
| 出错 | 3 次错误 → 冷却 3 秒 + 「叫爸爸妈妈帮忙」；**不锁死、不惩罚** |
| 忘记 | 点「帮忙」→ 家长门 → 家长端可重置任意孩子的密码 |
| 与家长密码区别 | 孩子密码保护**进入自己的页面**（弱、4–6 位、不锁死）；家长密码保护**设置/导出/支付**（强、6 位、5 次错误退回） |
| 显示 | 选人页卡片显示「有密码」标记；无密码的孩子点卡片直接进入 |
**使用管理**：到点内容墙「眼睛要休息啦」；延长仅家长门可操作。

# 附：四条实现判断标准

> 需要"把所有数据查出来再给模型"的代码，就是要删掉的代码。
> 需要"每周重置一次数据"的功能，都是设计错误。
> 摘要里出现星星数，是 bug；摘要里丢了孩子的情绪或约定，是事故。
> 孩子端点不中的按钮、拍不了的照、传不上去的图，都是设计缺陷，不是用户问题。
