## 一、必须改的 8 处

### 修订 1｜触控目标：48px 不够，要 64–80px

**证据**：NN/g 明确推荐儿童触控目标 **2cm × 2cm**（约 75–80px），是成人 1cm 标准的**四倍**；Smashing 给的是最小 75×75px、正文字号 18–19px。原文还记录两个 7 岁孩子因 5mm 关闭按钮点不中、误触广告而放弃 App。

**v3 原设计**：主按钮 ≥48×48、正文 ≥14px。

**v3.1 修订**：

| 元素 | v3 | v3.1 |
| --- | --- | --- |
| 主操作按钮（打卡/兑换/提心愿） | 48px | **≥64px 高，常用 ≥72px** |
| 次操作（返回、切换） | 48px | ≥56px，且与主操作间隔 ≥16px |
| 卡片内整卡可点 | 有 | 保留，但卡片内**不放两个相邻小按钮** |
| 正文字号 | 14px | **16px 起**；说明文字 14px；数据 28px 保留 |
| 底部导航文字 | 10px | **≥12px**（10px 已低于儿童可读下限） |
| 危险/关闭类小按钮 | 无 | 孩子端**不出现**；只允许大按钮 |

---

### 修订 2｜7 格底部导航是风险项，改 5 格 + 首页卡片

**证据**：Smashing 明确"**避免底部按钮，孩子经常误触**"；NN/g 的儿童测试反复出现误触相邻目标、误入广告的问题。同时 7 个 10px 标签在一行，既低于字号下限，也超出儿童"一次看 5 个以内选项"的可用范围。

**v3 原设计**：7 格底部导航（本周/阅读/动起来/说说话/闯关/商店/我的），保留 8 页骨架。

**v3.1 修订（推荐方案 A）**：

```
底部导航 5 格（≥72px 高，图标 26px，标签 12px，左右各留 8px 安全边）
┌────────────────────────────────────┐
│  本周    阅读    动起来   说说话   我的  │
└────────────────────────────────────┘

商店 / 闯关 / 签到 → 首页「我的小世界」三个大卡片（≥96px 高，横排或 2+1）
┌──────────┐ ┌──────────┐ ┌──────────┐
│  🎁 商店  │ │  🗺 闯关  │ │  🥚 签到  │
│ 心愿 85% │ │ 待闯 5 关 │ │ 今天 2/4 │
└──────────┘ └──────────┘ └──────────┘
```

- **8 个页面一个不删**，只是把入口从"常驻导航"改成"首页卡片"。孩子的实际高频路径是 任务→打卡→看心愿，商店/闯关是阶段性进入，常驻反而增加误触与认知负担。
- 若坚持 7 格（方案 B）：导航条高度提到 **80px**、标签 12px、图标 24px、格间距 ≥4px，并在底边留 12px 安全区避免拇指误触。**不推荐**，因为这是证据里最明确的问题模式。

**取舍说明**：这会改动 v3 里的导航结论，属于有依据的结构性修正，不是审美偏好。

---

### 修订 3｜"3/8" 这种数字，孩子读不懂，要画出来

**证据**：NN/g 认知研究——7 岁孩子会盯着屏幕上的数字 "2" 说"这个 2 是什么意思？好烦"，因为她无法把数字与目标（救 2 只小狗）建立联系；正确做法是同时给出**目标状态 + 当前状态 + 操作方式**三个可视化要素。皮亚杰阶段：6–10 岁跨前运算期与具体运算期，抽象数字必须锚定具体图形。

**v3 原设计**：`本周宝箱 3 / 8`，配进度条。

**v3.1 修订**：

```
本周宝箱
[🎁][🎁][🎁][ ][ ][ ][ ][ ]      还差 5 个
 ↑ 已开3个，未开5个，格子数量=家长设的任务数
```
- 分母不是数字，是**真实格子**（家长设 6 项就 6 格）；孩子用手指能数。
- 任务卡同理：`2 / 5 次` 改为 **5 个小圆点，2 个填满**（3 个以内用点，>5 用"3颗/共7次"折中并配点阵）。
- 心愿进度：`85/100 ⭐` 改为**星星填充条 + "再攒 15 颗"**，数字只做辅助。
- 全站原则：**能用图形表达的进度，不用分数**。

---

### 修订 4｜说说话不能靠打字：默认语音 + 气泡

**证据**：NN/g 记录 5–11 岁儿童"经常打错字、拼不出词"，高度依赖搜索引擎的自动纠错；打错就搜不到结果时孩子会明显受挫（"我明明看过那个视频，但 'exploding' 怎么拼？"）。6–8 岁儿童的精细动作与键盘能力都有限。

**v3 原设计**：说说话为自由文本输入 + 4 个快捷气泡。

**v3.1 修订**：
1. **首选语音输入**（大麦克风按钮 ≥72px，按住说话），识别失败自动转文本候选。
2. **快捷气泡升为主路径**：`我今天表现怎么样`·`陪我复盘`·`我想许个愿`·`讲个故事`·`夸夸我`，一屏可见、可横滑。
3. 文本输入保留，但**拼音/错字容错**是硬要求（"叫叫阅读"打成"叫叫yuedu"也能命中）。
4. AI 回复长度上限：**孩子端每条 ≤40 字 + 1 个表情符号**，超长拆成两条；不做长段落。
5. 不出现自由文本搜索框。

---

### 修订 5｜家长门不是 4 位 PIN，是"大人才能答的题"

**证据**：Apple 1.3 强制要求——Kids Category 应用**不得包含外链、购买机会或对儿童的其他干扰，除非放在家长门之后**；BabyBus 的实证做法是内容墙要求"识别繁体中文数字"，对孩子极难、对家长极简单（NN/g 原文特别点出这是"利用儿童认知局限设计非儿童界面"的正例）。

**v3 原设计**：4–6 位 PIN，5 次错误静默退回。

**v3.1 修订**：家长门 = **两层**

```
第 1 层：认知题（一次性，每次都答）
   「点击七」  四个大按钮：七 / 二 / 九 / 五
   「3 + 4 = ?」  六选一
   ↑ 家长一眼过，6-10 岁未掌握或会犹豫；随机题库 20+ 道

第 2 层：PIN（4-6 位）
   ↑ 防止孩子看过家长答题后重放
```
- 家长门后才是：家长端、外链、购买、导出、删除。
- 孩子端**完全没有**外链、购买、广告、分享（Apple 1.3 硬要求，也顺带砍掉一整类风险）。
- 家长门默认 15 分钟失效；家长端闲置 15 分钟自动退出。

---

### 修订 6｜星星经济会反噬：加三条内驱支柱

**证据**：Smashing 引 Rodrigo Seoane 的批评——"多数儿童产品依赖并制造**外在动机**依赖；奖励模型短期有效，长期会削弱认知投入并阻碍**内在动机**的形成"。SDT（Deci & Ryan）与 2024 年元分析一致：当奖励被感知为"控制手段"时，内在动机下降；当奖励承载"胜任反馈 + 自主选择"时，动机增强。

**v3 原设计**：星星是唯一驱动力（获得→消耗→心愿）。这是标准的"代币经济"，有把学习变成"打工"的风险。

**v3.1 修订**：保留星星，但把它从"工资"改成"记分"，并补三条内驱通道：

| 支柱 | 机制 | 落地 |
| --- | --- | --- |
| **自主 Autonomy** | 孩子有选择权 | 今天先做哪个任务由孩子定；宠物装饰/贴纸自选；心愿自己提 |
| **胜任 Competence** | 只看自己的进步 | 每任务有"我最快一次""连续 3 天"的个人最好记录；**永不显示排名或他人数据** |
| **关联 Relatedness** | 为关系而做，不是为星星 | "帮妈妈做一件小事"任务类型；布布记得孩子说过的事；家长端可写一句留言 |

配套三条减法：
1. **删掉"1⭐=1 元零花钱""1⭐=1 分钟动画"**——把星星与金钱/屏幕时间直接挂钩，是外驱最强、也最容易崩的设计。改为家长自行在商店里定义"用 20⭐ 换一次游乐场"，不做全局汇率。
2. **不做会清零的连续天数威胁**：断签不清零，只显示"重新开始第 1 天"，不出现"你失去了 7 天火焰"这种损失厌恶文案。
3. **不做"星星加速包/双倍时段"**：这是把成人增长手段搬到孩子身上。

---

### 修订 7｜防沉迷从 P1 提到 P0（且要合规）

**证据**：《移动互联网未成年人模式建设指南》要求产品提供**使用时段、时长、内容和功能的默认设置并允许个性化调整**，遵循**分龄原则**，并支持便捷切换与家长监护；BabyBus 的家长中心已被验证提供"连续使用上限 / 强制休息间隔 / 睡眠时段"三件套（NN/g 记录其到点展示内容墙）。NN/g 伦理段同时指出儿童自控力弱、更易沉迷。

**v3 原设计**：防沉迷列为 P1 评估。

**v3.1 修订（P0）**：家长端「使用管理」必须包含

| 设置 | 默认值 | 行为 |
| --- | --- | --- |
| 每日可用时长 | 40 分钟 | 到点后内容墙 + "今天到这里啦，明天见"，可由家长门延长 |
| 休息间隔 | 连续 20 分钟 | 强制休息 5 分钟（大图 + 呼吸动画，无内容） |
| 睡眠时段 | 21:00–07:00 | 时段内不可用，内容墙 |
| 分龄模板 | 按出生年自动 | 6–8 岁 / 9–12 岁两套模板（见修订 8） |

- 到点不"惩罚"孩子：文案为"眼睛要休息啦"，不是"时间到了，不能再玩"。
- 延长只能家长门操作（孩子端无入口）。

---

### 修订 8｜分龄：6–10 岁要拆成两套

**证据**：Smashing / NN/g 一致结论——**设计跨度不超过 2 岁**，3–5 / 6–8 / 9–12 三段在导航能力、阅读能力、手势能力上差异显著（9 岁起才具备复杂交互能力，11 岁才接近成人）。

**v3 原设计**：单一"6–10 岁"人设。

**v3.1 修订**：

| 维度 | 6–8 岁（低年级） | 9–12 岁（高年级） |
| --- | --- | --- |
| 文案 | 全图形 + 短句 + 语音朗读 | 图形 + 完整句子 |
| 打卡 | 一键 ±1，无需确认 | 可一次记多次数 |
| 数据呈现 | 只看"今天"和"宝箱" | 加"本周/趋势" |
| 布布口吻 | 更撒娇、短句 | 更像同伴、可讨论 |
| 家长端默认 | 任务 3–4 项、奖励 1–3⭐ | 任务 6–8 项、奖励可更高 |

出生年在首次引导填写后自动选模板，家长可覆盖。

## 二、被证据支持、保持不变的判断

| v3 判断 | 证据 |
| --- | --- |
| 孩子端"一屏一件事"、大按钮、单一主动作 | NN/g 物理发展研究：6–8 岁只用点击/滑动，拖拽困难 |
| 用孩子熟悉的隐喻（宝箱、闯关地图、宠物喂食） | NN/g 心智模型研究：孩子用"橡皮擦"而不理解"撤销"箭头 |
| 每个动作都要有反馈 | Smashing：孩子对每一次操作都期待反馈 |
| 家长是"最苛刻用户"，需要显性信任信号 | Smashing：家长在评分上"毫不留情"，愿为无广告付费 |
| 二孩零比较 | 与 SDT / 反攀比一致；无直接反证 |
| 家长定义一切 + 模板兜底 | 无直接研究，但符合"降低家长摩擦"的实践共识 |

### 补充两个具体做法（来自心智模型研究）

1. **错误恢复用实物隐喻**：打卡点错了，不显示"撤销"箭头，而是卡片上直接出现大按钮 **「点错了？改一下」**（孩子用橡皮擦而不是 undo）。
2. **指令不写具体设备**：不写"用鼠标点击"/"点击屏幕"，统一写 **「点这里」**（NN/g 案例：孩子因为指令说"用鼠标"而弃用更顺手的触控板，最后放弃游戏）。

## 三、合规硬约束（新增一节，非可选）

| 要求 | 来源 | 我们的做法 |
| --- | --- | --- |
| Kids Category 不得有外链、购买、干扰，除非在家长门后 | Apple 1.3 | 孩子端无外链/购买/分享；家长门后才有 |
| 不得向第三方发送可识别信息；不得含第三方分析/广告 | Apple 1.3 | 不接广告与三方分析 SDK；仅平台自有埋点 |
| 分龄原则 + 使用时段/时长/内容/功能默认设置可调 + 便捷切换 | 未成年人模式建设指南 | 见修订 7、8 |
| 14 岁以下需监护人同意，个人信息最小化 | PIPL / 未成年人网络保护条例 | 注册即家长身份确认；不采集孩子真实姓名（昵称即可）；头像本地/自选，不上传人脸识别 |
| 家长可查看、可删除孩子数据 | PIPL 同意撤回 | 家长端「删除该孩子全部数据」 |

## 六、还需要验证的假设（下一步）

研究给了方向，但这几条必须用真实孩子验证：

| 假设 | 验证方式 | 通过标准 |
| --- | --- | --- |
| 5 格导航 + 首页卡片优于 7 格导航 | 6–8 岁与 9–10 岁各 5 名，配对测试（dyad），任务"找到商店" | 找路成功率 ≥90%，误触率 <1 次/5 分钟 |
| 图形宝箱比 "3/8" 更易理解 | 问"还差几个才能开宝箱"，看是否指格子 | 6 岁组正确率 ≥80% |
| 语音输入是主路径 | 观察"跟布布说一句话"任务 | 无需成人提示完成率 ≥80% |
| 家长门题不挡家长 | 家长 5 人测，计时 | 首次通过 ≤10 秒 |
| 内驱三支柱是否有感知 | 访谈 + 一周观察 | 至少一半孩子主动提"我今天要先做 X" |

**测试方法注意**：3–5 岁单测、6–8 岁**配对测试更好**、9 岁以上可单测（NN/g 方法学）。儿童不适合填 SUS 问卷，评测用**任务完成率 + 观察到的挫败行为 + 主动要求继续玩**三项。
