# 视觉方向 v1（定稿）

> 依据：`PRODUCT.md`（register=product、三词：温柔/明确/值得信赖）+ `DESIGN.md`（令牌与组件）+ `ui-ux-pro-max` 检索结论。
> 本文只回答一件事：**布布看起来应该是什么样，以及用什么字体。**

---

## 一、方向判定：Claymorphism（克制版）

`ui-ux-pro-max` 对「children's app + habit + reward」的首选是 **Claymorphism**（软陶 3D）：

| 数据库建议 | 我们采纳 | 为什么改 |
| --- | --- | --- |
| 圆角 16–24px | ✅ 孩子端卡片 20 / 按钮 999 胶囊 | 采纳 |
| 双阴影（内 + 外） | ✅ 已有 `--clay-card` | 采纳 |
| 边框 3–4px | ⚠️ **改为 2px** | 4px 在 375 宽屏上会有"贴纸感"，且压缩内容区；2px 已足够软 |
| 粉彩色 → 靛蓝 #4F46E5 + 绿 CTA | ❌ **拒绝** | 品牌色已定（粉 `#FF85C1` → 紫 `#A855F7`），换色等于换产品 |
| 软弹动效 `cubic-bezier(0.34,1.56)` | ✅ 采纳（仅盖章/宝箱） | 与 `DESIGN.md §10` 一致 |
| 深色模式 | ❌ 不做 | 儿童白天使用 |

**一句话**：孩子端是**软陶质感**——厚一点的白卡、双阴影、胶囊按钮、按下有软回弹；但不是"捏橡皮泥"，没有 4px 描边、没有彩虹渐变、没有粒子。

家长端**不是软陶**：1px 边框、无阴影、灰白底、40px 控件。两端的"材质"本身就是身份区分。

## 二、字体（关键决策）

### 2.1 结论

| 用途 | 字体 | 来源 | 体积 |
| --- | --- | --- | --- |
| 中文（两端全部） | **系统栈**：`HarmonyOS Sans SC → MiSans → PingFang SC → Noto Sans SC → Microsoft YaHei` | 系统自带 | 0 |
| 数字 / 拉丁（孩子端） | **Baloo 2**（Semibold 600、Bold 700） | 自托管 woff2，只裁 Latin + 数字 | ~28KB |
| 数字 / 拉丁（家长端） | 系统 UI 字体 | 系统自带 | 0 |

### 2.2 为什么不用 Google Fonts 的推荐

`ui-ux-pro-max` 给出三组：`Noto Sans SC`、`Varela Round + Nunito Sans`、`Noto Serif TC`。全部否决：

| 候选 | 否决原因 |
| --- | --- |
| `Noto Sans SC`（Google Fonts） | **国内不可达**；自托管全量约 8–10MB，首屏不可接受 |
| `Varela Round` / `Comic Neue` | 无中文字形；`Comic Neue` 有手写感，**影响识字**（`DESIGN.md §3.1` 已明确不用手写体） |
| `Noto Serif TC` | 繁体衬线，与产品气质无关 |
| 全站 Baloo 2 | 无中文；中文若用圆体（幼圆类）笔画变形，6–10 岁正在识字，不能用 |

**所以**：中文交给系统（PingFang / HarmonyOS 的汉字质量本来就最好，且零加载、零 FOUT），**只把数字自托管**——因为数字是布布最常被"看见"的东西（星星、分钟、次数），圆润的数字值得花 28KB。

### 2.3 实现

```css
--font-kids: "HarmonyOS Sans SC", "MiSans", "PingFang SC", "Noto Sans SC",
             "Source Han Sans SC", "Microsoft YaHei", system-ui, sans-serif;
--font-number: "Baloo 2", "Nunito", var(--font-kids);

/* 只给"数字出现的地方"用，不给正文用 */
.bbu-num { font-family: var(--font-number); font-variant-numeric: tabular-nums; font-weight: 700; }
```

```html
<!-- 自托管，放 public/fonts/，不要用 fonts.googleapis.com -->
<link rel="preload" as="font" type="font/woff2" crossorigin
      href="/fonts/baloo2-700-latin.woff2">
```

**规则**
- 数字字体只用于：星星数、分钟数、次数、日期、倒计时、六位码。
- **不用于**：任务名、句子、按钮文案（中文必须走系统栈）。
- `font-display: swap`；数字字体加载失败时回落到系统数字，**不阻塞渲染**。
- 不做中文 webfont 子集化（维护成本高、且系统字体已足够好）。

## 三、材质与形状微调（相对现有 DESIGN.md）

| 项 | 现值 | 调整为 | 原因 |
| --- | --- | --- | --- |
| 孩子端卡片描边 | 1px `--k-border` | **2px** `--k-border` | 软陶需要"可见的边"，1px 在浅粉底上会消失 |
| 卡片阴影 | 双阴影 | 保持 | 已是 clay 标准做法 |
| 按钮高度 | 72 / 56 | 保持 | 触控优先已达标 |
| 家长端卡片 | 1px + 单层阴影 | 保持（更干净） | 家长端不 clay |
| 孩子端分区间距 | 12px | **16px** | 软陶件之间需要呼吸，12px 会"粘连" |
| 图标描边 | 2.2 / 2 | 保持 | lucide 2.2 在小尺寸更清晰 |

## 四、明确不做的视觉

| 不做 | 为什么 |
| --- | --- |
| 3–4px 粗描边 + 彩虹粉彩 | 变成"儿童玩具 App"套路，与"温柔但不幼稚"冲突 |
| 玻璃拟态 / 毛玻璃卡片 | 孩子端用不上；家长端已有足够层级 |
| 大模型光晕、粒子、打字机 | `PRODUCT.md` 反参考已列 |
| 全站 emoji | 已 0 emoji，且 emoji 在安卓/iOS 渲染差异大 |
| 中文圆体（幼圆/汉仪润圆） | 笔画变形影响识字 |
| 深色模式 | 儿童白天使用为主 |
