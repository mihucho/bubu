# 数据模型设计 v2（终版）

> **本文件是建表唯一依据**，替代 `数据模型设计-v1.md`（已归档）。
> 平台建表后执行 `npm run gen:db-schema` 生成 `server/database/schema.ts`，**不要手改**。
> 产品口径见 `最终方案-v2.0.md`；页面与链路见 `页面清单与链路-v1.md`。

## 一、八条铁律

1. **孩子是数据域**：业务表全部挂 `child_id`；`family_account_id` 冗余存一份，只用于家庭级校验与统计。
2. **星星只有一个真相**：`star_ledger`。`available_stars` / `total_stars` 只是事务内缓存，**业务模块不得直接改**。
3. **动作先落事件**：打卡、彩蛋、使用、闯关尝试都是事件表；计数字段是缓存，必须能重建。
4. **周期是任务属性**：不存在"所有任务按本周算"，`cycle_type` 决定达标口径。
5. **派生优于存储**：本周星星、本周达标、报告数字全部实时算，**不做每周重置任务**。
6. **幂等**：所有写接口带 `idempotency_key` 唯一约束。
7. **快照**：兑换记录、报告、消息保留当时的名称与数值。
8. **业务日用 `local_date`**（Asia/Shanghai），时刻用 `timestamptz`。

## 六、派生查询（不存字段）

```sql
-- ① 本周星星
SELECT COALESCE(SUM(amount),0) FROM star_ledger
WHERE child_id=$1 AND amount>0 AND local_date >= $weekStart;

-- ② 当前周期达标数（按任务自己的周期）
SELECT COUNT(*) FROM tasks
WHERE child_id=$1 AND is_active AND period_key=$2 AND is_achieved;

-- ③ 今日宝箱（分母 = 今天要做的任务数）
SELECT
  (SELECT COUNT(*) FROM tasks WHERE child_id=$1 AND is_active
     AND (cycle_type='daily' OR (cycle_type='weekly_days' AND EXTRACT(ISODOW FROM $today) = ANY(cycle_weekly_days)))) AS total,
  (SELECT COUNT(*) FROM tasks WHERE child_id=$1 AND is_active AND is_achieved
     AND (cycle_type='daily' OR (cycle_type='weekly_days' AND EXTRACT(ISODOW FROM $today) = ANY(cycle_weekly_days)))) AS done;

-- ④ 待确认数（家长端红点）
SELECT COUNT(*) FROM task_checkins WHERE child_id=$1 AND status='pending_confirm';

-- ⑤ 未读消息数
SELECT to_role, COUNT(*) FROM messages WHERE child_id=$1 AND read_at IS NULL GROUP BY to_role;

-- ⑥ 余额对账（应恒等于 available_stars）
SELECT COALESCE(SUM(amount),0) FROM star_ledger WHERE child_id=$1;
```

## 七、写星事务（唯一入口）

```ts
// common/stars.service.ts
async apply(tx, { childId, familyId, amount, reason, refTable, refId, title, localDate, idemKey }) {
  const existed = await tx.select().from(starLedger).where(eq(starLedger.idempotencyKey, idemKey));
  if (existed.length) return existed[0];                       // 幂等

  const [child] = await tx.select().from(childProfiles)
    .where(eq(childProfiles.id, childId)).for('update');       // 行锁

  const next = child.availableStars + amount;
  if (next < 0) throw new ConflictException('INSUFFICIENT_STARS');

  const [ledger] = await tx.insert(starLedger).values({ /* … */ balanceAfter: next }).returning();
  await tx.update(childProfiles).set({
    availableStars: next,
    totalStars: amount > 0 ? child.totalStars + amount : child.totalStars,
  }).where(eq(childProfiles.id, childId));
  return ledger;
}
```

**禁止**：任何模块直接 `UPDATE child_profiles SET available_stars`。

## 八、状态机一览

| 实体 | 状态 |
| --- | --- |
| 打卡 | `done` ⇄ `pending_confirm` → `done`（确认）/ `rejected`（退回） |
| 心愿 | `pending` → `priced` → `claimable` → `claimed` → （孩子确认）`kid_confirmed_at` ／ 任一 → `deferred` / `expired` |
| 兑换 | `done` → `refunded` |
| 关卡 | `pending` → `mastered` |
| 会话 | `active` → `idle`(10min) → `closed`(压缩) |
| 使用 | `active` → `resting`(5min) → `locked`(超时/睡眠) |
| 孩子 | `active` → `archived`(30 天可恢复) → 物理删除 |
| 同意 | `granted` → `revoked`（只读 7 天 → 注销） |

## 九、一致性校验（每日）

| 检查 | 判据 | 处理 |
| --- | --- | --- |
| 余额漂移 | `available_stars ≠ SUM(star_ledger.amount)` | 回写 + `adjust` 流水 |
| 打卡计数漂移 | `tasks.current_count ≠ COUNT(task_checkins WHERE status='done')` | 重建 |
| 达标不一致 | `is_achieved=true` 但计数未达 `cycle_target` | 重算 |
| 周期未滚动 | `period_key ≠ 按 cycle_type 计算的当前值` | 滚动并重置 `current_count/is_achieved` |
| 孤儿数据 | 业务表 `child_id` 不存在 | 标记 + 告警 |
| 报告缺失 | 有活动的区间无报告 | 补生成 |
| 消息未读堆积 | 同 kind 未读 > 20 | 折叠为一条 |
