# 「布布的学习小天地」产品优化方案 v2

> v1 基线：8 页导航 + 7 类业务数据 + 账号隔离 + AI 布布对话。
> v2 变更来源：新增三项硬约束——**二孩（家庭多孩）**、**孩子端独立设计**、**一切业务数据由家长定义**。
> 这三项不是加页面，而是改数据模型与端结构，因此 v2 把原 P0 前移一层，先立骨架再补体验。

---

## 一、决策摘要（v2 相对 v1 的变化）

保留 v1 的判断：不重构 8 页导航、激励闭环为主线、AI 从「会聊天」升级为「数据驱动的复盘者」。

v2 新增四项决策：

1. **账号模型从「一人一娃」改为「家庭 → 孩子 1:N」。** 登录主体是家庭账号；孩子档案是数据域，不是一个账号。所有 7 类业务数据必须挂在 `child_id` 上，星币、任务、商店、宠物、错题、心愿、AI 记忆**全部分孩子隔离**，不做家庭共享星星池。
2. **双端分离：孩子端 + 家长端，两个 shell，一道家长锁。** 孩子端只有「玩/看/点」，零设置、零导出、零删除；家长端承载全部配置、周报、导出，入口需家长 PIN。
3. **家长定义一切 = 配置中心，且每项都有系统默认值兜底。** 任务清单、任务奖励、彩蛋奖励、心情奖励、星星商店（物品/图标/价格/上下架）、孩子姓名/头像/称谓、周目标、宠物、AI 人设名、星星换算规则，全部家长可改；未配置时走模板，孩子端永远不会空。
4. **新增「星星流水」（star_ledger）作为一等公民。** 没有流水就没有周报、没有净消耗率、没有心愿进度可信度。这是 v1 遗漏的、v2 必须先补的地基。

二孩的产品底线：**孩子端永不出现任何横向比较**（无榜、无「姐姐比你多」）。家庭级对比仅存在于家长端，且默认收在「对比视图」里，不主动推送。

## 二、现状盘点（代码事实，供迁移决策用）

| 项 | 现状 | 对 v2 的影响 |
| --- | --- | --- |
| 登录主体 | `platformUserId`（平台账号）→ `kid_profile.platform_user_id` **唯一索引** | 一人一娃的硬约束，多孩必须解除 |
| 数据隔离字段 | 业务表用 `family_account_id`，但代码里实际写入的是 **`kid_profile.id`**（各 service 先 `resolveProfileId` 再写） | 命名与语义不一致，正好借迁移改名 `child_id`，比新增字段更干净 |
| 家庭账号表 | `family_accounts` 存了 `child_nickname`、`parent_role` | 孩子信息应上移到 `child_profiles`；家长身份留在 `family_accounts` |
| 默认数据种子 | 默认任务/商店/彩蛋分散写在 `auth.service.ts`、`kid.service.ts`、`shop.service.ts` 三处 | 抽成「家庭配置模板」，一处定义；家长改动持久化，模板只做兜底 |
| 星星变动 | `addStars`/`spendStars` 直接 update 计数，**无流水** | 无法出周报、无法算净消耗率 → v2 先加 `star_ledger` |
| 家长入口 | `/parent` 只是路由，孩子可随手点进 | 需 PIN 锁 + 家长端独立 shell |
| 任务奖励 | `tasks.star_reward` 已存在，但孩子端任务卡不展示，庆祝动画缺位 | P0 补「看得见的奖励 + 庆典」 |
| 导出 | 小日记导出为 `.txt` | 统一改图片导出（3:4 / 16:9），孩子端无导出入口 |

## 三、信息架构：三层账号 + 两个端

```
家庭账号 family_accounts（手机号/密码登录，家长身份、家长 PIN、周起始日）
   └── 孩子档案 child_profiles 1..N（姓名、头像、称谓、星星、宠物、AI 人设名）
          ├── tasks（本周任务，家长定义：名称/图标/次数/星星/排序）
          ├── egg_tasks（彩蛋，家长定义奖励数）
          ├── mood_records（心情与小日记，家长定义写心情奖励）
          ├── reading_records / exercise_records / reading_tracker
          ├── wrong_questions（孩子端呈现为「闯关」）
          ├── shop_items / exchange_records（商店家长定价、上下架）
          ├── wish_items（家庭心愿单，家长定价）
          ├── chat_messages（每个孩子独立的 AI 记忆）
          └── star_ledger（星星流水：来源、去向、child_id、时间）
   └── weekly_reports（按孩子生成）／ai_daily_reports（按孩子生成）
```

### 三端结构与路由

| 端 | 路由 | 谁进 | 内容 |
| --- | --- | --- | --- |
| 孩子端 | `/`、`/reading`、`/exercise`、`/chat`、`/wrong-questions`、`/stars`、`/checkin` | 孩子（无锁） | 7 个业务页 + 底部导航；**无设置、无导出、无删除、无周报** |
| 选人页 | `/choose` | 孩子 | 首次/主动切换时出现的大头像卡片页；设备记住上次孩子，日常不出现 |
| 家长端 | `/parent/*` | 家长（PIN） | 孩子管理、任务/商店/奖励配置、周报、导出、边界设置 |
| 首次引导 | `/setup` | 家长 | 建家庭 → 添加孩子 → 选模板 → 完成 |

关键规则：
- 底部导航的第 7 个入口从「家长」改为**「我的」**（头像 + 星星 + 宠物入口，孩子用语），「家长」入口移入设置齿轮或长按头像，点击弹 PIN。
- 家长端可在同一台设备上「退出家长模式」，回到孩子端，避免孩子看到配置界面。

## 四、数据模型变更（迁移方案）

### 4.1 表结构 diff

| 表 | 变更 |
| --- | --- |
| `family_accounts` | 增 `parent_pin`（4-6 位，哈希存）、`parent_display_name`、`week_start_day`（默认周一）、`setup_completed`；`child_nickname` / `parent_role` 迁出 |
| `child_profiles`（原 `kid_profile` 改造） | 增 `family_account_id`、`sort_order`、`birth_year`、`ai_persona_name`（默认=孩子昵称）、`ai_persona_avatar`、`star_rule_config`；**删** `platform_user_id` 唯一约束，改 `family_account_id` 索引 |
| 业务表（tasks/egg_tasks/mood/reading/exercise/chat/shop_items/exchange_records/wrong_questions/reading_tracker） | `family_account_id` → **`child_id`**；新增真实 `family_account_id`（仅用于家庭级统计与权限校验） |
| `star_ledger`（新） | `child_id`、`family_account_id`、`amount`（±）、`reason`（task/egg/mood/shop/wish/adjust）、`ref_id`、`balance_after`、`created_at` |
| `wish_items`（新） | `child_id`、`title`、`icon`、`star_cost`（家长定价，未定价→待定价态）、`status`（pending/priced/claimable/claimed）、`created_by`（kid/parent）、时间戳 |
| `weekly_reports`（新） | `child_id`、`week_start`、`payload`（jsonb 快照：达标、阅读/运动、星星收支、AI 摘要、下周建议）、`generated_at` |
| `ai_daily_reports`（新） | `child_id`、`report_date`、`payload`（今日总结、数据卡、鼓励语）、`generated_at` |
| `tasks` | 增 `icon_url`（家长 AI 生成图标，失败回退 `icon` 字符/SVG key）、`template_id`（可空，标识来自哪个模板）；`star_reward` 语义=该项达标一次性奖励 |

### 4.2 迁移步骤（有真实数据，必须可回滚）

1. 建 `child_profiles`（复制 `kid_profile`），回填 `family_account_id`（同一个 `platform_user_id` 视为一个家庭，家庭账号=该账号首个孩子对应的家庭记录）。
2. 业务表 `ADD COLUMN child_id`，`UPDATE child_id = family_account_id`（因为历史值就是 `kid_profile.id`），加索引与 NOT NULL 约束，**保留旧列一个版本双读**。
3. 建 `star_ledger`，用现有 `total_stars`/`available_stars`/`exchange_records` 生成期初流水（`reason=opening_balance`），此后所有加/减星改走流水 + 计数同事务更新。
4. 双写窗口内：读走 `child_id`，写同时写两列；确认无回归后删除旧列。
5. `family_accounts` 的昵称/角色迁移到 `child_profiles`，删除冗余列。

**验收**：迁移脚本跑两遍结果一致（幂等）；任取一个老账号，7 类数据条数、星星余额与迁移前完全一致。

## 五、二孩设计

### 5.1 家长端：孩子管理

| 能力 | 说明 |
| --- | --- |
| 添加孩子 | 姓名、头像（拍照/相册/预设）、称谓、出生年份（决定模板与口吻）、AI 人设名（默认同昵称） |
| 切换孩子 | 家长端顶部横向头像条；切换后所有配置页、周报、导出都跟随该孩子 |
| 排序 / 改名 / 删除 | 删除二次确认；有数据的孩子删除=归档（软删），不物理删除 |
| 一键复制配置 | 「用姐姐的任务和商店配置」→ 复制任务清单、商店物品、奖励数值到另一个孩子，家长不必录三遍 |
| 多孩对比（可选，P1） | 并排展示两个孩子的达标率/阅读分钟/星星收支，**仅在家长端**，默认折叠 |

### 5.2 孩子端：选人与隔离

- 进入即播「你要找谁呀？」选人页（大头像卡片，名字 + 今日星星），点击后进入孩子端；设备记住上次选择，日常直达。
- 切人入口只在孩子端「我的」页角落（"换一个人"），不做顶部切换器（避免孩子误触改数据域）。
- 全部分孩子隔离：任务、星星、商店、心愿、宠物、错题、心情日记、AI 对话记忆、周报。
- **每个孩子一个独立的布布**：人设名、头像、口吻独立。禁止「同一个布布同时夸两个孩子」造成的记忆串味与情感混淆。
- 服务端硬隔离：所有 API 以 `childId` 为参数并校验 `child.family_account_id === session.family_id`；越权返回 404（不用 403，避免探测）。

### 5.3 二孩专属边界

| 场景 | 规则 |
| --- | --- |
| 星星池 | 不共享。一个孩子的星星不能在另一个孩子身上花 |
| 姐姐已完成的任务 | 妹妹看到的是自己的进度，永不显示对方进度 |
| 同一设备并发使用 | 同一时刻只有一个「当前孩子」；切换不弹确认（孩子自己切），但每日只允许通过选人页切（防抖） |
| 家长误配 | 复制配置时二次确认；复制不覆盖已有进度（只复制定义，不复制计数） |
| AI 记忆 | AI 只读当前 `childId` 的数据，不得引用另一个孩子的任何记录 |

## 六、孩子端设计（Kids Mode）

### 6.1 设计原则

1. **一屏一件事**：每屏一个主动作；不做嵌套超过 2 层的页面。
2. **零设置**：孩子端不存在「管理/设置/删除/导出/周报」字样，也没有跳转入口。
3. **永不见失败**：错误文案一律正向（见 6.4 文案对照表），星星不足不说「失败」。
4. **可点即反馈**：任何点击 100ms 内有视觉反馈；奖励动作必须有动效 + 音效 + 语音表扬（可静音）。
5. **看得懂因果**：每个任务卡自带「做几次 → 得几颗星」，每页顶部四个数字卡可点开「我的星星从哪来」小账本（孩子版：图标 + 加号 + 星星数）。
6. **大触控**：按钮最小 48×48，卡片主操作整卡可点，字号不小于 12px（数据 28px）。

### 6.2 孩子端关键动效清单（P0）

| 触发 | 动效 | 备注 |
| --- | --- | --- |
| 任务打勾 | 印章盖章 + 星星飞入顶部数字卡（数字滚动） | 单次任务，非达标时 |
| 任务达标 | 卡片翻绿 + 星星入账 + 「+N 星」气泡 + 语音「哇，{昵称}好棒！」 | 一次一卡 |
| 本周全达标 | 全屏撒星庆典（3 秒，可点跳过）+ 累计奖励盘点 | 不阻塞后续操作 |
| 彩蛋开启 | 蛋壳裂开 + 彩带 | |
| 商店兑换 | 星星飞出 + 物品落入「我的背包」 | 消费确认一次 |
| 心愿攒满 | 进度条满格闪光 + 「可以找爸爸妈妈兑现啦」 | 兑付仍需家长确认 |
| 心愿进度 | 每次得星，心愿进度条同步 +1 小步 | 建立「攒星」感知 |

### 6.3 页面级变化（孩子端）

- **本周**：任务卡显示 图标（家长定义/AI 生成）+ 名称 + 「已完成 x/y · 完成得 N⭐」；顶部新增「布布说今天」卡片（AI 今日表现入口）；四数据卡可点开趋势小图。
- **阅读**：今日 + 本周双进度；宠物喂养用星星买食物（P1）。
- **动起来**：达标点亮火苗；周目标完成提醒。
- **说说话**：仅当前孩子的布布；进入先给一段「今日回顾」上下文（「我看到你今天读了 20 分钟…」）。
- **闯关记录**（原错题本）：地图式关卡，已通关打勾；统计保留「共 N 关 / 已通关 M 关」。
- **星星商店**：上方心愿区（进度条 + 差额），下方家长配置的兑换物品。
- **签到**：彩蛋（奖励数家长配置）+ 心情记录（奖励家长配置）；心情沉淀为日记素材。
- **我的**：孩子专属页——昵称、头像、宠物、星星账本、「换一个人」（切孩子）、齿轮（家长锁入口）。

### 6.4 儿童化文案对照（P0-5 落地口径）

| 成人/系统说法 | 孩子端说法 |
| --- | --- |
| 错题本 | 闯关记录 |
| 错题 / 已掌握 | 待闯关卡 / 已通关 |
| 达标 0/8 | 本周宝箱 0/8 |
| 目标 | 冒险目标 |
| 兑换成功 | 收到啦！ |
| 星星不足 | 再攒 N 颗就能换啦 |
| 今日无记录 | 今天还没有故事，要不要先闯一关？ |

### 6.5 家长锁

- 4-6 位 PIN（家长首次进入设置）。孩子端点齿轮/我的家长入口 → PIN 面板（大数字键盘，孩子可点但不知密码）。
- 连续 5 次错误静默退出到孩子端首页，不提示锁定（避免孩子试）。
- 家长端 15 分钟无操作自动退出家长模式。

## 七、家长定义一切：配置中心

### 7.1 配置项矩阵

| 类别 | 家长可定义的字段 | 默认值来源 | 是否必需 |
| --- | --- | --- | --- |
| 孩子档案 | 姓名、头像、称谓、出生年份、AI 人设名/头像 | 首次引导必填姓名头像，其余默认 | 是（姓名/头像） |
| 本周任务 | 名称、图标（字符/AI 生成图）、目标次数、达标奖励星星、颜色、排序、启用停用 | 模板「小学低年级」6 项 | 是（至少 1 项） |
| 任务周期 | 本周生效 / 自动继承上周 / 按星期重复 | 自动继承上周 | 否 |
| 彩蛋 | 每日数量、每个彩蛋星星数、彩蛋名称与图标 | 4 个 / 每个 1 星 | 是 |
| 心情奖励 | 写心情得星数 | 2 星 | 是 |
| 星星商店 | 物品名、图标、价格、描述、上下架、排序 | 模板 6 项 | 是（可空店，但需确认） |
| 心愿单 | 审批孩子提交的心愿并为它定价；家长也可代提 | 无 | 否 |
| 周目标 | 每周达标任务数（默认 8） | 8 | 是 |
| 宠物 | 名字、种类、初始状态 | 小黄油/小狗 | 否 |
| 换算说明 | 1 星 = 几分钟动画 / 几元零花钱（仅文案，用于规则说明页） | 1 分钟 / 1 元 | 否 |
| 边界 | 孩子端可见的 AI 话题边界、日记家长可见开关、导出开关 | 家长可见=开 | 是 |
| 提醒 | 阅读提醒、任务提醒、周报提醒开关 | 开（应用内） | 否 |

### 7.2 三条不变式

1. **永远有兜底**：任何未配置项走模板；孩子端不会出现空白或「未设置」。
2. **孩子端只读**：所有配置接口需家庭会话 + 家长模式；孩子端响应里不返回配置写接口的数据结构（避免前端被绕过）。
3. **改动只影响未来**：家长改奖励数/价格，已发放的星星不回滚、已兑换的订单不改价；生效范围在保存弹窗中明示（「下周起生效」/「立即生效」）。

### 7.3 首次使用向导（Onboarding）

1. 注册家庭账号 → 2. 添加第一个孩子（头像 + 姓名 + 出生年份）→ 3. 选模板（学前 / 小学低年级 / 自定义）→ 4. 确认任务清单与商店（可直接用模板）→ 5. 设家长 PIN → 6. 完成，进孩子端。

「添加第二个孩子」复用步骤 2-4，并提供「复制老大的配置」。

### 7.4 AI 生成任务图标

- 家长添加/编辑任务时可点「让豆包画一个」。输入任务名，调用豆包文生图（儿童友好、扁平、粉色系），返回 3 个候选 → 预览、重生成、选定。
- 失败降级：使用系统图标映射（按任务名关键词），**永不阻塞保存**。
- 存储：图标存文件服务，`tasks.icon_url` 保存地址；家长端保留「换回字符图标」。

## 八、本期范围（P0，共 7 项）

前置项 P0-0 / P0-6 必须先于其余项，因为它们改数据模型与端结构。

| 编号 | 核心改动 | 用户可见结果 | 验收要点 |
| --- | --- | --- | --- |
| **P0-0 家庭多孩地基** | 家庭账号→孩子 1:N；业务表 `child_id` 化；`star_ledger` 流水；服务端 childId 硬隔离 | 一个账号可建 2 个孩子，各自独立 | 给定家庭有 2 个孩子，当切换孩子时，任务/星星/商店/心愿/宠物/错题/对话记忆全部切换且互不可见；越权访问他人 childId 返回 404；迁移后老数据条数与余额一致 |
| **P0-6 家长配置中心** | 任务清单、奖励数、彩蛋/心情奖励、商店、心愿定价、周目标、孩子档案、AI 人设名的增删改 | 家长改完，孩子端立刻按新配置运行 | 家长未配置任何内容时，孩子端仍显示模板内容；家长修改奖励数后，新打卡按新值入账、历史不回滚；删除任务后任务卡消失但历史流水保留；AI 图标生成失败落系统图标且能保存 |
| **P0-1 奖励可见 + 完成庆典** | 任务卡展示每项可得星星；达标/全达标庆典动画 + 语音 | 孩子知道做什么得几颗星，完成有仪式感 | 完成最后一项任务触发庆典并撒星，可用星星按家长设定值增加；同一任务重复打卡不重复加星；庆典不阻塞操作 |
| **P0-2 AI 成长日报** | 说说话页「布布说今天」入口，基于当日真实数据复盘；对话前注入当日变更摘要 | 问「我今天表现怎么样」得到真实复盘 | 当日有任务/阅读记录时回复引用真实数字；当日无记录时如实说明并鼓励，不编造 |
| **P0-3 家庭心愿单** | 商店新增心愿区，孩子提交、家长定价、进度条 | 攒星奔大目标 | 攒满可兑付且余额正确扣减并写流水；不足时不可兑付并提示差额；重复点击不重复扣减 |
| **P0-4 家长周报** | 每周按孩子生成，含达标、阅读/运动趋势、星星收支、AI 摘要、下周建议 | 家长每周看一份总结 | 周报数字与各页一致（同一 childId、同一周）；无数据时展示空态不编造；二孩家庭各自一份 |
| **P0-5 闯关记录儿童化** | 错题→关卡、掌握→通关，文案与视觉闯关化，统计保留 | 孩子看到闯关地图 | 标记通关后通关数 +1 且不再出现在待闯列表；历史错题数据完整保留 |

## 十、AI 布布（多孩版）

- **人设卡**（每个孩子独立一份）：名字=该孩子的 AI 人设名（默认=孩子昵称）；年龄 6-10；性格天真爱撒娇；家庭记忆=该孩子业务数据 + 该孩子对话摘要 + 家长称谓。
- **数据协议**：回复前读取**当前 childId** 的 7 类数据 + 当日变更摘要 + 昨日回顾；严禁读取其他孩子数据；数据缺失时如实说「今天还没有记录」。
- **边界**：不编造数字、不评价家长、不转述家长负面评价、不引导孩子相互比较（「姐姐今天做得比你好」这类禁止生成）、不生成危险内容。
- **家长可见**：对话记录与日记默认家长可见（家长端可看摘要，全文按开关）；导出仅家长操作。

## 十三、风险

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| 多孩比较压力 | 二孩场景天然诱发「谁更棒」 | 孩子端零比较；家长端对比默认折叠；AI 禁止生成比较句式 |
| 迁移风险 | 现有数据 `family_account_id` 语义错误（存的是 profileId） | 双写窗口 + 幂等脚本 + 余额校验；先备份再迁移 |
| 家长配置门槛 | 全自定义=全要家长动手 | 全部有模板兜底；模板一键套用；「复制老大的配置」 |
| 二孩成本（AI、星币） | AI 对话按孩子计费 | 按孩子限频；日报每天一次缓存 |
| 家长锁被孩子破解 | 4 位 PIN 可能被看到 | 允许 6 位；5 次静默退回；家长端 15 分钟超时 |
| 图片导出兼容 | 移动端 WebView 保存相册受限 | 服务端渲染 PNG + 原生保存/长按保存兜底 |

## 十四、待确认问题

1. 二孩是否共用同一台设备为主？（默认：以同一设备为主，故做「选人页 + 设备记忆」；若每孩独立设备，选人页可弱化为首次设置）
2. 是否允许家长自定义「星星兑换换算」（1 星=几分钟动画/几元零花）作为商店条目模板？（默认：只做文案说明，不参与计算）
3. 家长 PIN 是否 P0 必做？（默认：必做，否则二孩+配置中心会让家长入口风险放大）
4. 二孩是否要「家长端并排对比」？（默认：P1 折叠视图，不在孩子端出现）
5. 任务「自动继承上周」是否默认开启？（默认：开启，家长改一次长期生效）
6. 孩子端是否保留「换一个人」入口？（默认：保留在「我的」页底部，需长按 1 秒）

## 附录：P0-0 落地清单（给研发）

1. schema：`child_profiles`、`star_ledger`、`wish_items`、`weekly_reports`、`ai_daily_reports`；业务表加 `child_id`。
2. 会话：middleware 解析 `family_account_id`；统一 `resolveChild(req, childId?)` helper，默认「家庭当前孩子」（`family_accounts.current_child_id`）。
3. 服务层：所有 service 的 `platformUserId → profileId` 改为 `familyId + childId`；读写均带 `family_account_id` 校验。
4. 星币：`addStars/spendStars` 改为事务内写 `star_ledger` + 更新 `child_profiles` 计数。
5. 前端：`ProfileContext` 升级为 `FamilyContext`（family + children[] + currentChild）；`AppContext` 按 child 重建；新增 `ParentModeContext`（PIN 状态）。
6. 默认模板：`server/config/templates.ts` 单点定义任务/商店/彩蛋/奖励默认值，三处旧种子删除。
7. 灰度：迁移脚本 `--dry-run` 输出差异报告；先跑测试库，再灰度 1 个真实家庭。
