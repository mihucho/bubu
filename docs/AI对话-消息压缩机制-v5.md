# AI 对话 v5：消息自动压缩机制

> 前置：`docs/AI对话-工具化改造-v4.md`（工具化 + 多轮）。
> 本文解决多轮带来的新问题：**对话越长，上下文越脏、越贵、越慢，而且旧消息里的过期数字会污染回答。**

---

## 一、核心原则（四条，先立后写）

### 原则 1：压缩的是「提示词视图」，不是数据

数据库里的 `chat_messages` **永远只增不改**，一条不删。压缩只决定"这一轮往模型里塞什么"。
理由：家长可回看全文（v3 合规要求）、可导出、可审计；模型看到的是摘要，家长看到的是原文。

### 原则 2：数字不进长期记忆，需要时再查

这是压缩机制里最重要的一条判断。

- 旧消息里的"你有 121 颗星"在一周后是**错的**，但它会被摘要"忠实"地带进新对话 → 模型据此编造。
- 所以压缩时**主动丢弃所有数字**，只保留"孩子关心过星星/阅读"这类语义；需要数字时走工具（`get_child_profile` / `get_today_snapshot`）。
- 摘要里唯一允许保留的数字：日期、孩子主动说的稳定事实（"我 8 岁"）、未完成约定的到期日。

### 原则 3：情绪与承诺永不压缩掉

孩子说"我今天很难过，因为数学没考好"——这是安全信息，压缩掉就等于系统失忆。
所以摘要必须**单独保留**两类：`emotions`（情绪事件）与 `open_loops`（答应过的事）。

### 原则 4：压缩是异步的，且失败可回退

- 触发在**回复结束之后**，不阻塞当前这一轮（否则用户等两次生成）。
- 压缩失败 → 保留原文继续用，打 `compact_failed` 标记，下轮重试；超过硬上限才强截断。
- 摘要**可重建**：原始消息在，任何时候能重算。

## 二、三层记忆模型

```
┌─ L0 工作记忆（原文窗口）───────────────────────────┐
│ 最近 12 条 user/assistant 原文，≤1200 token        │
│ 特点：完整、精确、有指代上下文                       │
└───────────────┬───────────────────────────────────┘
                │ 溢出 → 压缩
┌─ L1 会话摘要（滚动摘要）───────────────────────────┐
│ 单个 session 的滚动摘要，结构化 JSON + 一行自然语言  │
│ 体量恒定 ≤200 字 / 300 token（增量合并，不线性增长） │
└───────────────┬───────────────────────────────────┘
                │ session 结束 / 跨天 → 提炼
┌─ L2 长期画像（跨 session）─────────────────────────┐
│ 稳定事实：喜好、禁忌、家庭结构、重要事件、里程碑      │
│ ≤10 条 / 300 token，带 first_seen / last_seen       │
└───────────────────────────────────────────────────┘
```

**一轮注入的预算（孩子端）**

| 块 | 预算 | 说明 |
| --- | --- | --- |
| system（人设+铁律） | 800 token | 静态可缓存 |
| L2 长期画像 | 300 token | ≤10 条 |
| L1 会话摘要 | 300 token | ≤200 字 |
| L0 原文窗口 | 1200 token | ≤12 条 |
| 工具结果 | ≤1500 token | 本轮临时 |
| **合计** | **≤4100 token** | 家长端放宽到 6000 |

> 有预算才有压缩：**每一层都设硬上限，超了就压。**

---

## 三、触发条件

| 触发 | 阈值 | 动作 |
| --- | --- | --- |
| 条数溢出 | 未摘要消息 > 16 条 | 把最老的一半（≥6 条）压进 L1 |
| Token 溢出 | 未摘要部分 > 1800 token | 同上，按 token 切 |
| 会话空闲 | 距最后一条 > 10 分钟 | 后台整体压一次，并尝试提炼 L2 |
| 跨天 | `local_date` 变化 | 强制压 L1，把"昨天"的事实提炼到 L2 |
| session 关闭 | 新 session 开启时 | 旧 session 全量压 L1 → 提炼 L2 |
| 手动 | 家长端"整理记忆" | 立即全量压缩 |

**防抖**：单轮最多触发一次压缩；同一 session 两次压缩间隔 ≥30 秒；压缩中再次触发直接跳过。

## 四、摘要结构（可校验的 JSON）

不要写"一段自由文本摘要"——不可校验、会漂移、无法增量合并。用固定 schema：

```json
{
  "v": 1,
  "summary": "聊了今天的作业和数学小测，情绪从沮丧转为被鼓励；约定明天讲恐龙故事。",
  "facts": [
    { "k": "喜欢的活动", "v": "拼图和恐龙", "at": "2026-03-10" },
    { "k": "数学", "v": "最近有点吃力，怕被比较", "at": "2026-03-11" }
  ],
  "emotions": [
    { "emotion": "难过", "cause": "数学小测没考好", "at": "2026-03-11", "handled": true }
  ],
  "open_loops": [
    { "text": "答应明天讲恐龙故事", "due": "2026-03-13", "done": false }
  ],
  "avoid": ["不要主动提爸爸出差"],
  "drops": { "numbers": 14, "tool_json": 6 }
}
```

字段规则：

| 字段 | 上限 | 规则 |
| --- | --- | --- |
| `summary` | 120 字 | 只写"事件 + 情绪走向 + 结论"，不写数字 |
| `facts` | 6 条 | 只收**稳定**信息；一次性话语不入 |
| `emotions` | 5 条 | 保留最近 7 天；`handled` 表示是否已安抚 |
| `open_loops` | 4 条 | 未完成约定，过期 3 天自动丢弃 |
| `avoid` | 3 条 | 孩子明确表达的禁忌（"别说我胖"） |
| `drops` | — | 压缩统计，用于观测 |

**校验**：`facts` 每条必须能被来源消息 id 反查（存 `source_message_id`）；`emotions` 必须命中情绪词典；否则整条丢弃并记 `invalid_summary`。

## 五、压缩算法

### 5.1 增量合并（关键：摘要体量恒定）

```
输入：existing L1 summary (可能为空) + 一批待压缩消息 (chunk)
输出：new L1 summary（体量不增长）

1. 抽取：从 chunk 中抽出
   - 事件句（做了什么/说了什么）
   - 情绪句（情绪 + 原因）
   - 约定句（答应/要约/明天）
   - 稳定事实句（喜欢/不喜欢/家里谁）
   - 删除：所有数字、所有工具 JSON、所有重复寒暄
2. 合并：existing + extracted → 按字段去重（facts 按 k 合并取最新，emotions 按 at 截断最近 5 条）
3. 收敛：超过上限 → 优先丢 facts 里 last_seen 最老的、再丢 emotions 里 handled=true 且 >3 天的
4. 校验：schema parse + 来源可溯 → 失败则只保留上一个版本
```

**复杂度**：`O(1)`。压 10 次和压 1 次，摘要体量一样——这正是"滚动摘要"和"每 10 条写一段新摘要"的区别。

### 5.2 伪代码

```ts
// compaction.service.ts
async function compact(session, opts: { reason: string }) {
  const unsummarized = await loadMessagesSince(session, session.summaryCursor, { limit: 24 });
  if (!unsummarized.length) return;

  const chunk = unsummarized.slice(0, Math.max(6, Math.floor(unsummarized.length / 2)));
  const existing = await loadSummary(session);            // 可能是空

  const prompt = `
你是摘要器。把【已有摘要】和【新对话】合并成一份新摘要。
规则：
- 数字全部丢弃（星星、分钟、次数都不写），需要时系统会重新查询。
- 保留：孩子说的稳定事实、情绪及原因、答应过的事、明确禁忌。
- summary ≤120 字；只输出 JSON，符合给定 schema。
【已有摘要】${JSON.stringify(existing)}
【新对话】${renderCompactMessages(chunk)}
`;

  let next;
  try {
    next = await llm.json(prompt, SummarySchema);         // 强 schema
    validateTraceability(next, chunk);                    // facts 必须能溯源
  } catch (e) {
    await markCompactFailed(session, e);                  // 保留原文，下轮重试
    return;
  }

  await db.transaction(async (tx) => {
    await upsertSummary(tx, session.id, next, { cursor: chunk.at(-1).id });
    await upsertFacts(tx, session.childId, next.facts, chunk);   // 写 L2 候选
  });

  // 记录压缩比与丢弃项，供观测
  log.info({ session: session.id, in: chunk.length, outBytes: JSON.stringify(next).length,
             numbersDropped: next.drops.numbers, reason: opts.reason });
}
```

### 5.3 蒸馏到 L2（长期画像）

```
触发：session 结束 / 跨天 / 家长端手动
输入：L1 summary
规则：
  - facts 出现 ≥2 次且跨 ≥2 个 session → 升级进 L2（置信度 0.8）
  - 单次提到但属"禁忌/过敏/特殊需求" → 立即进 L2（置信度 0.9）
  - 30 天未再出现的普通 fact → 降权，90 天未提及 → 软删除
  - emotions 不进 L2（情绪是会话级，不做长期标签，避免给孩子贴标签）
```

> **不做孩子人格画像**：L2 只存"事实与偏好"，不存"性格评价"（如"胆小""爱哭"）。这是儿童产品的伦理红线。

## 六、什么必须保留、什么必须丢弃

| 内容 | 处理 | 原因 |
| --- | --- | --- |
| 星星数、阅读分钟、任务次数 | **丢弃** | 会过期，且可通过工具重查；留在摘要里必然导致编造 |
| 工具返回的 JSON | **丢弃** | 体量大、重复、无对话价值 |
| 寒暄/重复确认（"嗯""好的"） | **丢弃** | 纯噪音 |
| 孩子情绪 + 原因 | **必留** | 安全信息，且是"被记得"的核心体验 |
| 孩子明确表达的喜好/禁忌 | **必留** | 直接影响下次回答是否得体 |
| 答应孩子的事（故事、约定） | **必留 + 到期提醒** | 失约会摧毁人设可信度 |
| 家长负面评价（"妈妈说你太慢"） | **丢弃，不外传** | v3 边界：AI 不转述家长负面评价 |
| 账号/手机号/地址等 PII | **脱敏后丢弃** | 合规 |
| 危机信号（被打、害怕、不想活） | **必留 + 升级** | 见 §7 |

## 七、安全例外：情绪危机不走普通压缩

```
命中危机词表（害怕/打我/不想活/没人喜欢我…）
→ ① 该条消息打 safety_flag=true，永久保留，不参与压缩丢弃
→ ② 当轮强制生成安抚话术（不等待工具调用）
→ ③ 家长端「需要关注」条目 + 推送（家长可见开关默认开）
→ ④ 摘要里 emotions.handled=false，后续对话优先回访
```

这条规则**优先级高于所有压缩预算**：宁可超 token，不可忘记孩子在求助。

## 八、与工具化的关系（分工写清）

| 问题 | 谁来回答 |
| --- | --- |
| 「我今天表现怎么样」 | `get_today_snapshot`（不要靠记忆） |
| 「上周读了多久」 | `get_reading(days=7)`（记忆里没有也不该有） |
| 「你上次说讲恐龙故事」 | **L1 `open_loops`**（工具查不到） |
| 「我最喜欢什么」 | **L2 `facts`**（工具查不到） |
| 「我叫什么」 | `get_child_profile`（权威）+ L2 兜底 |

**判断标准**：能被数据库查到的事实，绝不写进记忆；只有"关系与约定"才进记忆。

## 九、数据表

```sql
chat_summaries(
  id uuid pk,
  child_id uuid,
  session_id uuid,
  level text,              -- 'session' | 'long_term'
  payload jsonb,           -- 上面的 schema
  covers_from_message_id uuid,
  cursor_message_id uuid,  -- 已压到哪条
  tokens_in int, tokens_out int,
  version int,             -- 每次合并 +1
  compact_failed_at timestamptz,
  created_at, updated_at
)

chat_memory_facts(
  id uuid pk,
  child_id uuid,
  key text, value text,
  confidence numeric,      -- 0..1
  first_seen date, last_seen date,
  source_message_id uuid,
  deleted_at timestamptz   -- 软删（孩子或家长要求忘记）
)
```

**孩子端的「不要记得这个」**：孩子说"你别记这个"，调 `forget_memory(key)` → `deleted_at` 置位，摘要下次合并时不再带出。这是给孩子的一点点掌控感，也是隐私合规的加分项。

## 十、降级与兜底

| 情况 | 行为 |
| --- | --- |
| 摘要模型超时 / 非法 JSON | 保留原文，标 `compact_failed`，下轮重试；连续 3 次失败 → 降级为"每 12 条硬截断最老 6 条"并告警 |
| 仍超硬上限（如一次灌入大量语音转写） | 硬截断：保留 system + L1 + 最后 6 条；被截断的消息在家长端仍可见 |
| 摘要与工具结果冲突（摘要说 100 颗、工具说 121） | **工具优先**，且把摘要里的数字清掉（本来就不该有） |
| 家长清空记忆 | `chat_summaries` + `chat_memory_facts` 全部软删，原文保留 |

## 十一、观测指标

| 指标 | 口径 | 目标 |
| --- | --- | --- |
| 压缩触发率 | 压缩次数 / 对话轮数 | 0.08–0.15（过低说明没压，过高说明窗口太小） |
| 压缩比 | 压缩前 token / 压缩后 token | ≥8:1 |
| 摘要体量漂移 | 第 N 次压缩后摘要 token | 波动 <20%（验证体量恒定） |
| 召回抽查 | 每周人工抽 20 条摘要，看关键信息是否保留 | ≥95% |
| 数字污染率 | 摘要中出现数字的比例 | =0 |
| 压缩失败率 | `compact_failed` / 压缩次数 | <1% |
| 危机漏保留 | safety_flag 消息被丢弃的次数 | =0（硬红线） |

## 十二、样例（真实走一遍）

```
原始 18 条（节选）
  kid: 我今天数学考了72分，好难过
  bub: 抱抱，72 分已经比上次进步啦…
  kid: 可是妈妈说我太粗心
  bub: 我们下次一起先检查一遍好不好？明天我讲恐龙故事给你听
  kid: 好！我喜欢霸王龙
  kid: 我有几颗星星了
  bub: 你有 121 颗啦（← 工具查的）

压缩后 L1
{
  "summary": "聊了数学小测，情绪从难过转为被鼓励；答应明天讲恐龙故事。",
  "facts": [{ "k": "喜欢", "v": "霸王龙", "at": "2026-03-11" }],
  "emotions": [{ "emotion": "难过", "cause": "数学72分并觉得被说粗心", "at": "2026-03-11", "handled": true }],
  "open_loops": [{ "text": "答应明天讲恐龙故事", "due": "2026-03-12", "done": false }],
  "avoid": ["不要转述妈妈的负面评价"],
  "drops": { "numbers": 3, "tool_json": 1 }
}
```

**注意**：`121 颗星` 被丢弃（可随时查）；`72 分` 被保留在 emotions 里作为**原因**而非事实数据（它是稳定事件，不是会变的统计）。这个区分就是压缩质量的分水岭。

## 十三、落地顺序

| 阶段 | 内容 |
| --- | --- |
| C1（0.5 天） | `chat_summaries` 表 + schema 校验 + 滚动摘要（只做 L1，异步、失败回退） |
| C2（0.5 天） | 压缩触发（条数/空闲/跨天）+ 防抖 + 计量日志 |
| C3（1 天） | 危机信令例外 + 家长端「需要关注」+ 忘记记忆 |
| C4（1 天） | L2 长期画像 + 蒸馏规则 + 家长端「查看/清理记忆」 |
| C5 | 摘要质量抽检脚本 + 每周报告 |

## 附：一句话判断标准

> 摘要里出现具体星星数或分钟数，就是 bug；
> 摘要里丢掉了孩子说过的情绪或约定，就是事故。
